# Rune Code 인크리멘탈 PoC

하나의 마법을 노드 그래프로 연결하고 확장하는 Unity 게임이다. 스테이지에서 직접 이동·조준하며 오른쪽으로부터 몰려오는 적과 제한시간 동안 전투한 뒤, 처치 보상 RAM으로 마나풀과 전투시간을 강화한다. Unity 6000.3.22f1 / Windows x64를 사용한다.

마법 그래프 규칙의 기준은 `Assets/Docs~/Refactoring/마법 그래프 구현 규칙.md`이고, 2026-10-08 리팩토링 계획과 결정은 같은 폴더의 `마법 그래프 리팩토링 계획.md`에 있다.

## 실행

`Builds/RuneCodePoC-ManualMods-Windows.zip`을 모두 압축 해제한 뒤 `RuneCodePoC.exe`를 실행한다. 실행 파일과 `_Data`, `UnityPlayer.dll`, `MonoBleedingEdge`를 함께 유지한다. 이전 빌드와 ZIP은 보존한다. 기존 빌드는 리팩토링 전 버전이며 새 규칙은 다시 빌드해야 반영된다.

Editor에서는 `Assets/Scenes/RuneCodePoC.unity`를 열고 Play한다. `Rune Code > Prepare PoC Scene`은 기존 장면과 글꼴 연결을 유지하며 한국어 문자를 준비한다. `Rune Code > Build Windows PoC`의 출력은 `Builds/RuneCodePoC-ManualMods/RuneCodePoC.exe`다.

## 플레이 흐름

1. 작업실에서 기본 마법(시전 → 투사체)의 노드를 편집하고 시험 도크에서 시전해 토큰 흐름을 확인한다.
2. 출격 탭에서 해금된 스테이지를 선택한다. 기본 전투시간은 30초다.
3. WASD로 이동하고 마우스로 조준한다. 전투 영역을 좌클릭할 때마다 마법을 한 번 시전한다(누르고 있어도 반복하지 않는다). Space는 대시, G는 그래프 오버레이, Esc는 일시정지다.
4. 제한시간까지 생존하면 처치 RAM 100%를 정산하고 다음 스테이지를 해금한다. 사망·중단은 처치 RAM의 70%를 반올림해 지급한다.
5. 결과의 `마법 강화`로 같은 설계를 계속 확장한다. `같은 스테이지 재도전`으로 반복 수급할 수 있다.

## 마법 그래프

시전하면 마나풀에서 적재량만큼 마나를 실은 **토큰**이 생겨 흐름선을 따라 노드를 지나간다. 토큰은 노드에 도착할 때마다 그 순간의 위력·개수로 계산한 비용을 내고, 낼 수 없으면 그 노드에서 소멸한다. 모든 노드 종류를 개수 제한 없이 쓸 수 있다.

| 노드 | 포트 | 효과 | 비용 |
|---|---|---|---|
| 시전 | 0 / 1 | 토큰 생성(적재량 10~100, 조준: 커서 / 가장 가까운 적) | 0 |
| 투사체 | 1 / 1 | 개수만큼 발사. 출력이 없으면 남은 마나를 투사체에 실음 | 2 × 개수 |
| 증폭 | 1 / 1 | 위력 × 배율(1.1~3.0) | 위력 × (배율 − 1) × 0.4 |
| 가산 | 1 / 1 | 위력 + 10 | 3 |
| 분열 | 1 / 1 | 개수 + 1, 위력 × 0.7 | 위력 × 0.15 |
| 분배 | 1 / 2 | 남은 마나를 비율(10~90%)로 나눠 두 갈래 | 2 |
| 합류 | 2 / 1 | 양쪽 토큰의 마나·위력·개수 합산, 1초 안에 짝이 없으면 혼자 진행 | 2 |
| 분기 | 1 / 2 | 대상 거리·대상 체력%·마나·위력·세대·통과 횟수 조건 | 1 |
| 적중 | 0 / 1 | 마나를 실은 투사체가 적에게 맞으면 이 자리에서 새 토큰 | 0 |

시전·적중을 뺀 모든 비용은 최소 1이다. 투사체는 직선으로 날아가 적 하나에 맞으면 사라지며 `max(0, 위력 − 경감)` 피해를 준다. 잡몹은 경감 12라 기본 위력 10으로는 피해를 주지 못하므로 위력을 키워야 한다. 역방향·자기 연결로 루프를 만들 수 있다.

## 별도 강화

**보유 RAM**은 적 처치로 얻는 구매 재화다.

| 강화 | 시작 비용 | 단계당 효과 |
|---|---:|---|
| 마나 | 15 RAM | 마나풀 최대 +10, 초당 회복 +1 (기본 100 / 8) |
| 전투시간 | 18 RAM | +5초 (기본30초, 최대120초) |

다음 가격은 `ceil(시작 비용 × 1.22^현재 단계)`다. 마나는 최대100단계, 전투시간은18단계다. 그래프에 구조 오류가 있으면 출격할 수 없다.

## 노드 편집과 시험

| 동작 | 조작 |
|---|---|
| 배치·연결 | 팔레트 클릭/드래그, 노드 이동, 출력 포트에서 입력 포트로 드래그(같은 출력의 기존 연결은 교체) |
| 화면·선택 | 중간 버튼 또는 빈 곳 우클릭 드래그, 휠 확대, Shift 다중 선택, 빈 곳 영역 선택 |
| 삭제·검색 | Del/Backspace 노드 삭제, 연결선 우클릭 삭제, 빈 곳 더블클릭 검색 |
| 복사·편집 | Ctrl+C/V 노드 복사·붙여넣기, Ctrl+D 노드 복제, Ctrl+Z/Y 되돌리기·복구, Ctrl+S 저장 |
| 시험 도크 | 도크 클릭·시험 버튼·1 키로 1회 시전, 배속, R 초기화 |

노드에는 비용 공식과 파라미터가 표시되고, 시전·적중에서 닿지 않는 노드는 회색이다. 도크에서 시전하면 편집 화면 위로 토큰이 엣지를 따라 움직이고, 노드마다 토큰 수(`×N`), 마지막 지불 비용, 소멸 표시(지불 불가 `필요 X / 보유 Y`, 수명 초과)가 나온다. 그래프를 바꾸면 도크의 토큰·투사체는 모두 지워진다. 전투 중에는 그래프 편집이 잠긴다.

## 저장과 이전 진행

`Application.persistentDataPath/runecode.save.v3.json`에 단일 마법, RAM, 성장, 스테이지와 설정을 저장한다. Windows 기본 경로는 `%USERPROFILE%\AppData\LocalLow\DefaultCompany\w06-test2`다.

v3가 없으면 v2(또는 v1)를 읽어 RAM·성장·스테이지·설정을 이전하고, 옛 룬 그래프는 새 노드와 호환되지 않으므로 기본 그래프로 다시 시작한다. 이전 파일은 수정하지 않는다. 그래프 공유(RC1)는 제거되었다.

설정 화면에서 진행을 초기화할 수 있다. `.backup`과 `.invalid-backup`은 같은 저장 폴더에 보관한다. F8은 최대500건의 로컬 기록을 출력한다. 실행 인수 `-debug`는 RAM 지급·무적·적 소환 도구를 표시한다.

## 시뮬레이션 CLI

프로젝트 루트의 PowerShell에서 새 Windows 빌드를 이용한다.

```powershell
.\tools\sim.ps1 -Scenario incremental -Ticks 6000 -Seed 1 -Stage 1 -Output Builds/incremental-sim.json
.\tools\sim.ps1 -Spell C:\path\my-graph.json -Scenario incremental -Ticks 6000 -Stage 2 -Duration 35 -EnergyLevel 1 -CastInterval 20
.\tools\sim.ps1 -Scenario dummy_line -Ticks 600 -Seed 1
```

`-Spell`은 마법 그래프 JSON 파일 경로이며, 없으면 기본 그래프를 쓴다. `-CastInterval`(기본 30틱)마다 한 번 시전한다. `incremental`은 비교용 자동 조준 입력을 사용하며 종료·사망 시 멈춘다. `-Duration 0`은 JSON의 기본30초다. 도크 시나리오는 `dummy_single`, `dummy_line`, `dummy_swarm`, `aegis`, `adapt_loop`다.

JSON에는 피해, DPS, 마나 사용량, 노드 지불 횟수, 최대 동시 투사체, 실행 시간, 상태 해시, 스테이지, 제한시간, 종료 상태, 처치·획득·정산 RAM이 담긴다. CLI는 사용자 저장을 변경하지 않는다.

## 데이터와 검증

`Assets/RuneCode/Resources/RuneCode/balance.json`의 `_spell` 섹션이 마법 그래프의 모든 수치(위력, 마나풀, 비용 계수, 머무는 시간, 투사체, 상한)를, `enemies.json`이 적 체력·경감을, `incremental.json`이 제한시간·유입·스테이지 배율·적 편성을 관리한다. 게임 규칙은 Core, 표시와 입력 연결은 Game/UI, 저장은 Save에서 처리한다.

실제 검증과 미검증 항목은 `docs/PROGRESS.md`, 변경 결정은 `docs/DECISIONS.md`에 기록한다. AGENTS.md에 따라 Git CLI·커밋·push와 테스트 코드·자산 추가는 수행하지 않는다.
