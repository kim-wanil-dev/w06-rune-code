# PRD — 모듈형 마법 리메이크

- 작성일: 2026-10-07
- 문서 버전: 0.1
- 상태: 구현 전 요구사항 초안. 기능·동작 기준이며 밸런스 초기값은 별도 조정 가능하다.
- 작업 계획: [PLAN_MAGIC_REMAKE.md](PLAN_MAGIC_REMAKE.md)
- 적용 범위: Rune Code의 단일 활성 마법 설계·시전·전투 효과·편집·저장·공유.
- 기존 PRD와 충돌하는 마법·시전 규칙은 이 문서를 우선한다. 전투 단계·정산·성장 규칙은 기존 인크리멘탈 기획을 따른다.
- 사용자 확정 입력: 기본 시전을 마우스 클릭·홀드로 통일한다. 포인터 위치만으로 시작되는 기존 전투 자동 시전은 대체한다.

## 1. 목표

여러 형태 모듈에 속성·수식·제약·강화를 각각 적용하고, 앞 모듈의 사건을 다음 모듈의 입력으로 연결하여 하나의 마법으로 사용한다. 형태의 순서와 연결 사건이 바뀌면 다른 전투 동작을 만든다.

조건을 추가해 사용 기회·자원·행동 자유를 제한하면, 지정한 모듈 또는 구간에 명시적인 강화 보상을 받는다. 사용자는 무엇을 포기하고 무엇을 얻는지 편집기와 전투 화면에서 확인할 수 있어야 한다.

완료 상태에서 아래 세 마법을 편집기로 조립하고 도크와 실제 전투에서 실행할 수 있어야 한다.

1. 무기 전격 주입 → 평타 적중 → 연결선 → 2초 유지 → 적 중심 흡입 영역.
2. 얼음 창 낙하 → 지면 착지 → 십자 방향선 4개 → 끝점 집계 → 외곽 얼음 장벽.
3. 관통선 → 대상별 불안정 마력 주입 → 해당 대상 사망 또는 3초 경과 중 먼저 발생한 사건 → 대상 위치의 마력 가시.

- 자동으로 적 조합과 조건 성공률을 추정하는 강화 산정 시스템.

## 3. 설계 모델

### 3.1 노드와 연결

```text
입력/Core → 형태 A
               └ 사건 출력 → 트리거 → 제약·강화 → 형태 B → 후속 사건
속성·수식 ────────────────────────────┘
```

| 요구 ID | 요구사항 |
|---|---|
| G-01 | 활성 그래프 하나를 하나의 마법으로 시전한다. 각 형태 노드는 독립적인 속성·수식·제약·강화 설정을 가진다. |
| G-02 | Core는 시전 진입점이다. 형태는 효과와 사건을 생성하고, 트리거는 사건을 선별·대기·집계하여 후속 실행을 생성한다. 제약·강화 노드는 조건 검사·대가 지불·보상 적용을 한 묶음으로 표시한다. |
| G-03 | 실행 연결, 사건 연결, 속성/수식 부착 연결을 구별한다. 사건 출력은 트리거 입력으로, 트리거 실행 출력은 후속 실행 입력으로 연결한다. 일반 실행을 사건 입력에 연결하는 오류는 차단한다. |
| G-04 | 생성 사건에 연결하면 앞 형태가 유지되는 동안 다음 형태도 존재할 수 있다. 정상 완료 사건에 연결하면 앞 형태가 끝난 뒤 다음 형태가 실행된다. 화면 좌표나 노드 번호가 실행 순서를 바꾸지 않는다. |
| G-05 | 하나의 출력에서 여러 후속 노드를 실행할 수 있다. 여러 실행 출력을 한 입력에 임의로 합치지 않는다. 다중 개체 집계는 지정한 집계 트리거로 수행한다. |
| G-06 | 기존 지연·반복·조건 분기는 사용할 수 있다. 단순 분기·지연·적중 연결 자체는 강화 보상을 자동 발생시키지 않는다. |
| G-07 | 실행 순환은 금지한다. 재발사·반복·재사용 대기시간 초기화는 횟수와 수명이 있는 명시적 기능으로만 구성한다. |
| G-08 | 형태당 속성은 최대 1개, 속성·일반 수식 부착은 합계 최대 3개를 초기값으로 유지한다. 제약·강화는 별도 실행 노드로 RAM을 점유하며 부착 슬롯을 쓰지 않는다. 무속성은 속성 미부착의 기본값이다. |

### 3.2 후속 실행에 전달하는 정보

사건은 시전 ID, 노드 ID, 모듈 개체 ID, 소유 시전자, 사건 순번/틱, 발생 위치·방향, 대상 ID, 효과를 받은 개체 ID, 종료 원인, 실제 피해/차단량, 형제 생성 묶음 ID를 전달한다. 대상이 삭제된 뒤에도 마지막 위치·방향·사망 원인은 남는다.

- **발동 위치:** 시전자 현재 위치 / 사건 발생 위치 / 대상 현재 위치 / 모듈 끝점 / 집계 중심 중 선택한다.
- **발동 방향:** 시전 때의 조준 / 현재 조준 / 사건 진행 방향 / 공격이 온 방향의 반대 / 지정 대상 방향 / 방사형 중 선택한다.
- **대상:** 사건 대상 또는 명시적 검색 규칙을 사용한다. 대상 없는 사건에서 대상 요구 모듈을 연결하면 컴파일 오류다.
- **대상 소멸:** 대상 추적이 필수인 모듈은 취소한다. 위치 기반 모듈은 마지막 위치로 실행할 수 있다. 다른 적을 자동 대체하지 않는다.
- **정보 보존:** 상태·수치 조건은 트리거 실행 직전의 상태를 검사한다. 위치·방향은 선택한 스냅샷/추적 방식에 따른다.
- **구간 적용:** 후속 마법은 앞 마법의 강화·속성을 자동 상속하지 않는다. 전달 범위를 지정한 강화와 대상 주입 효과만 적용한다.

### 4.1 형태별 필수 경계

- 직선/곡선은 2D 평면 경로다. 낙하의 높이는 시각적 준비 표현이며, 지정한 2D 착지점에서 1회 착지 사건을 낸다. 3D 지면 충돌을 전제하지 않는다.
- Vector의 방사 배치에는 개수·각도 간격을 설정하며 대표 예시는 십자 4갈래다. 순간 광선은 경로 계산 완료 때 끝점/종료 원인을 확정하고, 이동 매체는 실제 이동 종료 때 확정한다. 둘 다 거리 끝 트리거에 연결할 수 있으나 벽 때문에 짧아진 경로는 지형 충돌로 분류한다.
- Construct의 질량감은 충격량·피격 경직·밀기·화면 표현으로 구현한다. 물리 질량에 따른 실제 3D 강체 시뮬레이션은 요구하지 않는다.
- 장벽은 시뮬레이션 이동/투사체 판정에 참여한다. 아군 마법 통과는 기본 허용하며 변경 가능한 설정이다. 겹친 장벽을 이유로 적을 피해 없이 삭제하지 않는다. 생성 위치에 겹친 적은 가장 가까운 유효 위치로 보정한다.
- 연결은 대상이 존재하고 거리·시야/장벽 조건이 허용될 때만 성공한다. 단절 사건에 거리 초과·장벽·대상 사망·정상 종료·사용자 취소 원인을 포함한다.
- Infusion이 적/투사체에 부여될 때 시전자 자신에게 효과를 잘못 적용하지 않는다. 무기 주입의 적중 사건은 실제 캐리어 적중에서 발생한다.
- Domain의 규칙은 영역 안에서만 적용한다. 종료·이탈 시 감속 등 임시 규칙을 해제한다. 중첩 영역의 감속은 가장 강한 값을 사용하고, 피해/힘은 설정 상한 안에서 합산한다.
- 같은 캐리어에 같은 노드가 재주입되면 기본적으로 지속시간 갱신, 중첩 프로필이면 지정 상한까지 증가한다. 자신이 발생시킨 주입/부여 사건을 다시 주입하는 무한 연결은 차단한다.
- 상태 카탈로그는 기존 화상·냉기·빙결·EMP와 새 불안정 마력·출혈·기절 프로필을 제공한다. 불안정 마력은 부여/사망/기한 관측을 소유한다. 출혈은 설정된 주기 피해, 기절은 이동·공격 중지이며 중첩/면역/재부여 정책은 각 프로필에 명시한다. 도크·조건 선택과 전투 적용이 같은 상태 ID를 사용한다.
- 적 보호막 소진 트리거를 위해 적의 선택적 보호막 수치를 HP와 별도로 다룬다. 기존 적의 기본 보호막은 0으로 유지하고 도크에서 양수 보호막 사례를 제공한다. 이지스의 전방 피해 감쇠/EMP 무력화는 보호막 HP 소진과 구별한다.
- 유지형 Root/캐리어는 중복 생성·교체·갱신 정책을 표시한다. 기본은 같은 시전자/노드의 기존 개체 갱신이다. 새 시전에서 이전 개체를 교체하면 교체 원인 종료이며 정상 완료 보상을 내지 않는다.

### 6.2 반복·관측 범위

- 각 트리거는 1회만/대상별 1회/최대 N회/최소 발동 간격/누적 N회 후 1회 정책을 가진다. 무제한은 제공하지 않는다.
- 임계값 사건은 조건 범위로 들어가는 순간 발생한다. 조건이 참인 모든 틱에 반복 발생하지 않는다. 다시 발동하려면 범위 밖으로 나간 뒤 재진입해야 하며, 명시한 재무장 정책과 횟수 상한을 따른다.
- 임계값 관측 등록 시 현재 상태를 1회 평가하는 것을 기본으로 한다. 이미 범위 안이면 최초 사건을 1회 낼 수 있으며, 관측이 유지되는 동안 동일 값 때문에 다시 발동하지 않는다. 등록 시 평가를 끄는 설정도 표시한다.
- 상태 보유 검사는 입력 사건에 대한 필터다. 상태 변화 사건을 기다리는 트리거와 UI에서 구별한다.
- 누적량의 관측 범위는 원본 모듈 개체/동일 시전 계보/부여 대상별 중 하나를 명시한다. 서로 다른 시전의 피해·스택을 암묵적으로 합산하지 않는다. 상태 프로필이 명시적으로 캐리어별 지속 중첩을 제공할 때만 시전 간 축적한다.
- 직접 피해/지속 피해 포함 여부를 설정한다. 초과 피해가 아니라 실제 감소한 HP/보호막을 누적한다.
- 지연 실행은 단일 소유 개체/부여 상태에 묶인다. 소유자가 정상 종료·파괴·해제되어 취소되는 정책을 명시하며 마지막 위치 실행을 지원할 수 있다.
- 생성, 유지 틱, 실제 피해, 상태 변화, 사망, 종료의 동시 사건은 정해진 순서와 사건 ID로 처리한다. 같은 피해에서 처치 보상·사망 후속·상태 제거가 중복 처치로 기록되지 않는다.
- 입력 사건은 살아 있는 해당 그래프/시전/모듈의 관측 범위 안에서만 처리한다. 대상 상태의 사망 관측은 캐리어 제거 전 마지막 정보를 확보한다.

### 7.2 강화와 기존 수식의 관계

- 사거리·크기·속도·유도·관통·다중 등 일반 수식은 해당 형태에서 효과가 있을 때만 적용한다. 효과 없는 조합은 경고를 표시한다.
- 피해/범위/지속/구속/이동 힘/분열/비용 환급/재사용 초기화 강화는 제약 프로필이 허용한 항목과 상한 안에서 선택한다.
- 제약 강도와 보상은 데이터의 등록 프로필로 짝을 맞춘다. 조건 성공률을 추정해 런타임에서 보상을 임의 증가시키지 않는다.
- 단순 시간 경과는 위험이 낮은 지연이다. 정지·공격 불가·EN 소모 등 추가 대가가 있는 차징/유지에만 해당 강화 프로필을 허용한다.
- X², 피해 300%, 범위 +200%, 즉사 등 사용자 예시의 숫자는 자동 공통식이 아니다. 보상 프로필별로 기본값·최대값을 표시한다. 범위 +200%는 반경/길이 3배인지 면적 3배인지 구분하며 이 문서의 예시는 반경/길이 3배다.
- 보상은 해당 범위에만 적용한다. 물려받은 강화는 각 후속 노드에서 다시 곱하지 않는다. 중첩 프로필은 합성 순서와 총배율 상한을 가진다.
- 재사용 초기화는 해당 시전 1회 및 별도 내부 쿨다운을 기본으로 한다. 새로운 Root를 즉시 실행하지 않고 다음 사용자 입력을 허용한다. 연쇄 재발사는 별도 제한 횟수로 설정한다.

| 처치 회수 | 이 계보의 실제 처치 사건 | EN 일부 회수 또는 Root 재사용 초기화, 발동 횟수 상한 적용 |
| 열충격 | 동결된 적에게 화염 효과가 적용되고 동결 소모 | 방어 감쇠 우회 피해 또는 설정 HP 이하 일반 적 처형 |

열충격은 등록된 반응으로만 제공한다. 보스의 무조건 즉사는 기본적으로 허용하지 않는다. 처형 가능 대상·HP 기준·방어 우회 범위는 프로필에 표시하며, 이 정책과 수치는 밸런스 제안값이다. 발동 예시의 Burst는 독립된 일곱 번째 형태가 아니라 Wave의 순간 방사 변형으로 표현한다.

### 7.4 EN·RAM·쿨다운

| 요구 ID | 요구사항 |
|---|---|
| R-01 | 점유 RAM은 배치된 모든 노드를 합산한다. 같은 부착 노드를 공유하면 노드 RAM은 1회 계산하되 각각의 효과 실행 비용은 따로 계산한다. 제약을 달아 RAM 용량 자체를 무료로 늘리지 않는다. |
| R-02 | 새 그래프는 단계별 실제 실행 비용을 지불한다. 최악 경로 예상 EN은 편집기 정보이며 현재 EN보다 높다는 이유만으로 전체 그래프를 거부하지 않는다. 단일 필수 지불이 최대 EN을 초과하는 것은 오류다. |
| R-03 | 실행 순서는 사건 검증 → 제약 검사 → 모든 지불 가능 여부 확인 → 원자적 지불 → 강화 확정 → 형태 실행이다. 해당 단계 실패 시 일반 실행 비용과 추가 대가를 일부만 빼지 않는다. |
| R-04 | EN 비율 대가는 기준을 최대 EN/현재 EN으로 표시한다. 기본은 최대 EN 기준. 현재 EN 기준은 최소 절대 지불량을 함께 요구한다. 현재 EN 0에서 무료 고배율 보상을 얻지 못한다. |
| R-05 | 형제 후속은 안정적인 순서로 각자의 EN을 지불한다. 한 분기의 EN 부족이 이미 실행된 형제의 비용을 되돌리거나 복제하지 않는다. 전체/구간의 추가 대가는 진입 시 첫 필수 실행 비용과 함께 지불하며, 이후 모듈의 일반 비용은 각 실행 시점에 지불한다. 모든 미래 분기의 비용을 예약하지 않는다. |
| R-06 | 유지형은 시작 비용+표시된 유지 비용, 차징은 준비 시작 비용+발사 비용이다. 미발동 예약은 비용을 지불하지 않는다. 이미 사용한 준비/유지 비용은 취소 시 환불하지 않는다. 처치 회수는 실제 지불 비용 범위 안에서만 환급한다. |
| R-07 | 재시전 사건도 지불·제약·빈도 규칙을 거친다. Root 쿨다운과 트리거 내부 쿨다운은 별개이며 어느 하나를 초기화해도 다른 제한은 유지한다. |
| R-08 | 새그래프의 점유 RAM에 따른 기본 Root 쿨다운은 기존 계산을 재사용한다. 입력이 눌린 채 있는 것만으로 쿨다운 이후 새 차징을 시작하지 않는다. |

## 8. 실행 순서·종료·상한

- 같은 틱은 입력/이동 → 준비/예약 → 모듈 진행/충돌 → 피해·상태/사망 → 사건 정렬/후속 → 종료 정리 순서로 처리한다. 새로 생성된 모듈은 해당 틱에 생성 사건을 내지만 이동·충돌은 다음 틱부터 수행한다.
- 동시 후속 정렬은 사건 틱·시전 ID·개체 ID·노드/연결 ID로 고정한다. FirstOf의 같은 틱 우선순위는 별도로 적용한다.
- 적중은 유효 충돌, 피해 누적은 실제 피해, 처치는 생존→사망 전환이다. 한 적의 처치는 1회다. 사망 원인과 기여 계보를 유지한다.
- 반복 틱이나 생성 사건을 이용한 연쇄에도 깊이·발동 횟수·예약·개체 상한이 적용된다. 한계 때문에 생략된 노드와 이유를 도크/진단에서 표시한다.
- 전투 종료·플레이어 사망·도크 리셋·마법 교체·앱 비활성화로 해당 실행을 취소하면 예약·입력 관측·대상 관측·집계와 임시 상태를 정리한다. 이러한 취소는 정상 종료/처치/파괴 보상을 만들지 않는다.
- 수명 종료 후에도 남아야 하는 대상 사망/지연 가시 효과는 별도 수명을 가진 Infusion 상태가 소유한다. Root의 종료만으로 자동 삭제하지 않되, 전투 종료 취소는 우선한다.
- 시간·곡률·확률/노이즈 선택은 시뮬레이션 틱과 기존 시드에 기반한다. 동일 그래프·설정·시드·입력으로 동일한 사건과 결과를 얻는다.

## 11. 대표 시나리오의 정확한 동작

### A — 전격 채찍·자기장

1. 좌클릭으로 무기 Infusion 캐리어를 활성화한다. 이후 좌클릭/홀드 평타로 전격 적중을 만든다.
2. 대상별 평타 적중에서 Tether를 생성한다. 동일 대상의 연결은 갱신하고 연속 유지 타이머를 새로 시작한다.
3. 거리/시야 유지 제약을 2초 연속 충족하면 해당 대상의 현재 위치에 Domain을 1회 생성한다.
4. Domain은 살아 있는 주변 적을 중심으로 끌어당긴다. 중심 대상 사망 시 중심은 마지막 위치에 고정되고 Domain은 자신의 수명까지 유지한다.
5. 연결이 2초 전에 끊기면 Domain은 생성되지 않는다. 실패한 후속 EN은 지불하지 않는다.

### B — 얼음 감옥

1. Construct 얼음 창을 선택한 2D 지점에 낙하·착지시킨다. 피해와 착지 사건은 각각 1회다.
2. 착지 사건에서 중심으로부터 4갈래 Vector를 생성한다. 단일 생성 묶음으로 식별한다.
3. 각 Vector의 거리 소진 위치를 AllOfGroup으로 집계한다. 네 점을 각도 순서로 연결하는 Wall을 1회 생성한다.
4. 장벽은 폐곡선 내부/외부의 적 이동을 막으며, 내구도·수명이 끝나면 해제한다. 완성 전 일부 Vector가 충돌하면 기본 정책에서 감옥은 완성되지 않는다.
5. 4개 끝점 사건이 4개의 완성 감옥을 생성하거나 서로 다른 시전의 끝점을 섞지 않는다.

### C — 불안정 마력·가시

1. 관통 Vector가 유효한 적을 맞힐 때 대상별 1회 Infusion을 부여한다. 관통한 각 적이 독립된 소유 상태다.
2. 부여 후 해당 적 사망과 3초 기한을 FirstOf로 관측한다. 해당 적의 사망은 이 공격 외 피해 원인도 포함한다.
3. 먼저 발생한 사건에서 대상 현재/마지막 위치에 Construct 가시를 1회 생성한다. 남은 예약/관측을 취소한다.
4. 같은 틱 사망+기한이면 사망 승자다. 가시 피해로 다른 주입 대상이 죽으면 그 대상의 가시가 이어질 수 있지만 계보 상한을 따른다.
5. 시체 오브젝트를 전제로 하지 않으며 적 제거 후에도 보관된 위치로 실행한다.
