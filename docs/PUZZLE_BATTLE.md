# 퍼즐 전투

# 플레이어에게 주고자 하는 경험
- 다음 순서대로 플레이하는 걸 의도했다.
- 불가능할 것 같은 조건을 확인한다.
    - 조건은 다음 요소들이 들어갈 수 있다.
        - 마나 회복량 0, 최대 마나 100에서 주어진 마나만으로 한정된 적 전부 처치
        - 마나 회복량 100, 최대 마나 10에서 약한 마법으로 제한시간내에 요구치 적 처치하기
        - 제한 시간 내에 적 일정수량 처치하기
        - 제한된 RAM으로 만든 마법들을 가지고 제한 시간 내에 스테이지 클리어
- 플레이어는 이 조건을 한번 해보고, 조건에 맞는 마법을 만든다.
- 내가 만든 마법으로 퍼즐을 풀고 쾌감을 느낀다.

## 1단계: 퍼즐 전투 진입과 기존 전투 재사용

### 목표

작업실 상단 메뉴의 `시간제 전투` 오른쪽, `설정` 앞에 `퍼즐 전투` 버튼을 추가한다. 퍼즐 전투에서도 기존 시간제 전투의 출격 UI와 내부 전투를 그대로 사용한다.

이 단계는 진입 경로를 마련하는 작업이다. 위 경험에 필요한 퍼즐별 제한 조건은 아래 2단계 기획에 정의한다. 아래 내용은 구현 계획이며 아직 구현 완료를 뜻하지 않는다.

### 플레이 흐름

1. 작업실에서 `시간제 전투` 또는 `퍼즐 전투` 버튼을 누른다.
2. 기존 출격 패널에서 스테이지와 현재 마법을 확인한다.
3. 출격하면 기존 마법 검증을 거쳐 미션 전투에 진입한다.
4. 기존 조작으로 전투하고, 결과 화면에서 재도전하거나 작업실로 돌아온다.

두 버튼은 같은 출격 패널을 공유하고, 현재 선택한 버튼만 강조한다. 1단계에서는 선택 스테이지, 플레이어 능력치, 적 스폰, 클리어 조건 및 재도전 동작을 기존 전투와 동일하게 적용한다. 퍼즐 진입에서는 보상을 지급하지 않는다. 제한 조건을 구현할 때는 아래 퍼즐 설정을 같은 화면과 전투 실행 경로에 전달한다.

### 작업 순서와 연결 대상

| 순서 | 대상 | 계획 |
|---|---|---|
| 1 | `WorkshopScreen` | 퍼즐 탭 ID를 추가하고 탭 순서를 맞춘다. 시간제 전투와 퍼즐 전투를 선택했을 때 같은 출격 패널을 표시한다. |
| 2 | `WorkshopPresenter` | 두 전투 탭에 진입할 때 기존 `DeployPresenter`를 갱신한다. 공유 패널의 버튼 이벤트는 기존처럼 한 번 연결한다. |
| 3 | `DeployPanel`, `DeployPresenter` | 스테이지 선택, 마법 표시, 출격 준비 검증과 미션 진입 경로를 공유한다. |
| 4 | `WorkshopScreen.prefab` | 퍼즐 버튼과 라벨을 추가하고 탭 버튼·라벨 배열 참조를 같은 순서로 연결한다. 상단 능력치·재화 표시와 겹치지 않도록 배치한다. |
| 5 | `WorkshopLayout`, `strings.ko.json` | 신규 생성 시에도 같은 메뉴가 만들어지도록 빌더를 맞추고, `퍼즐 전투` 현지화 문구를 추가한다. |
| 6 | 기존 미션·결과 화면 | 두 진입점 모두 `MissionScreen` → `MissionRun` → `RuneSimulation` 경로와 기존 결과·재도전 흐름을 사용한다. |

현재 `WorkshopLayout.Build()`는 화면 Prefab이 이미 존재하면 생성을 건너뛴다. 따라서 생성 코드와 기존 `WorkshopScreen.prefab`의 버튼·배치·참조를 함께 반영해야 한다.

### 완료 기준

- `시간제 전투` 옆에 `퍼즐 전투`가 표시되고 두 버튼의 선택 강조가 올바르다.
- 두 버튼을 번갈아 눌러도 같은 출격 UI가 표시되고 스테이지·마법 정보가 갱신된다.
- 같은 스테이지와 마법으로 기존 전투에 진입하며 조작·스폰·클리어 규칙이 동일하다. 퍼즐 진입의 보상 지급은 없다.
- 일시정지, 전투 중단, 결과 표시, 재도전, 작업실 복귀가 기존 흐름으로 동작한다.
- 반복 전환과 재도전 시 클릭 이벤트가 중복 처리되지 않고 퍼즐 보상이 지급되지 않는다.
- Unity 컴파일과 화면 Prefab의 버튼·라벨 참조 연결을 확인한다.

## 2단계: 제한 조건 기획 구체화

### 목표와 범위

문서 상단의 네 가지 경험을 각각 하나의 퍼즐로 구성한다. 플레이어는 `조건 확인 → 첫 시도 → 실패 원인 확인 → 마법 재설계 → 재도전 → 해결`을 반복한다. 해결은 특정 정답 그래프와 비교하지 않고 전투 목표 달성으로 판정한다.

이번 단계의 산출물은 아래 네 퍼즐의 기획이다. 보상, 보상형 해금, 추가 퍼즐 유형은 구성하지 않는다. 조건 적용 코드와 전투 자산은 아직 구현하지 않는다.

상단에 제시된 마나 조건은 그대로 사용한다. 새로 정한 시간·수량·RAM 값은 첫 구현에 사용할 기획 설정값이다. 해법은 현재 룬 수치에 근거한 계산과 설계 예시이며, 적 이동·조준을 포함한 실제 클리어는 아직 검증하지 않았다.

### 네 퍼즐의 설정

| 퍼즐 | 시작 / 최대 마나 | 회복량 | RAM 용량 | 제한시간 | 적 수와 성공 조건 |
|---|---|---|---|---|---|
| P1: 주어진 마나로 전부 처치 | 100 / 100 | 0/s | 6 | 없음 | 유한한 적 12마리 전부 처치 |
| P2: 작은 마나통으로 빠르게 처치 | 10 / 10 | 100/s | 6 | 12초 | 유한한 적 24마리 전부 처치 |
| P3: 제한시간 내 목표 처치 | 100 / 100 | 15/s | 6 | 15초 | 등장하는 적 42마리 중 36마리 처치 |
| P4: 작은 RAM으로 스테이지 클리어 | 100 / 100 | 15/s | 2 | 12초 | 유한한 적 24마리 전부 처치 |

### 공통 조건과 플레이 흐름

- 기존 출격 패널, 마법 편집기, 미션 화면, 이동·조준·좌클릭 시전·대시·일시정지·결과 화면을 사용한다. 출격 패널의 기존 선택 조작으로 P1~P4를 선택한다. 네 퍼즐은 처음부터 선택할 수 있다.
- 매 시도에 활성 마법은 하나다. 여러 설계를 만들고 비교할 수 있으나 전투 중 슬롯 교체와 그래프 편집은 하지 않는다. 마법 호출을 사용하는 경우 호출 대상까지 기존 컴파일러의 RAM·문법 검사를 적용한다.
- 개인 성장 단계와 일반 스테이지 난이도 배율 대신 표의 고정 조건을 적용한다. HP는 100, 이동·대시·적 피해는 현재 기본 규칙을 사용하고 적응 감쇠는 적용하지 않는다.
- 전투 종류와 무관하게 같은 작업실 편집기·보관함·활성 마법을 사용한다. 룬 해금, Modifier 소지량, 성장으로 확보한 RAM과 마나, 편집 이력 및 시험 도크는 기존 작업실 규칙을 따른다. 퍼즐을 선택해도 편집 규칙이나 마법을 변경하지 않는다.
- 퍼즐 진입에서는 현재 마법의 문법과 선택한 퍼즐의 RAM 조건을 검사한다. 부적합하면 출격을 막고 이유를 표시하며 마법은 그대로 편집할 수 있다. 기본 마법을 새로 만들거나 퍼즐 전용 설계로 교체하지 않는다. `시작 조건(onAttack) → 구형(일반 속성) → 발사`는 아래 첫 시도 분석에 사용하는 예시다.
- 모든 목표 적은 기존 `enemy.scout`을 사용한다. HP 20, 반경·이동·공격은 현재 기본값을 적용하고 엘리트·분열·추가 증원은 없다. 아래 좌표는 시작 플레이어 위치를 원점으로 한 고정 위치이며 단위는 기존 시뮬레이션 px다.
- 동일 퍼즐을 재도전하면 HP·마나·시간·적·스폰 일정·쿨다운·예약 실행·마법 개체·상태이상을 초기화한다. 시작 위치와 난수 시드(1)는 동일하고 수정한 설계만 유지한다.
- 퍼즐은 성공·실패·중단 모두 재화, Modifier, 일반 스테이지 해금 및 일반 처치 기록을 지급·갱신하지 않는다. 결과 화면은 목표 달성 여부와 시도 결과를 표시한다.

### P1: 주어진 마나로 전부 처치

**주고자 하는 경험:** 무작정 시전하면 마나가 부족하지만, 한 번의 시전으로 여러 적을 맞히거나 지속 피해를 활용하면 같은 마나로 해결할 수 있음을 발견한다.

**적 구성:** 시작과 동시에 12마리를 배치한다. x는 240·290·340, y는 -180·-60·60·180인 4개 일렬 묶음이며 추가 스폰은 없다.

**첫 시도에서 드러날 문제:** 기본 일반 발사는 피해 10, 비용 8이다. HP 20인 적 12마리를 개별 2발로 잡으면 최소 192 마나가 필요하므로 100 마나로는 부족하다.

**설계 방향과 해법 예시:**

- 한 줄의 적을 관통하거나, 가까운 적을 모아 폭발로 함께 맞힌다.
- `구형(화염) → 발사 + 관통(C)`은 RAM 3, 실행 비용 11.6이다. 현재 컴파일러가 사용하는 내부 화염 룬 비용 2를 더한 값이다. 한 발이 같은 3마리를 맞힐 때 직접 피해는 10·9·8이며 화상 피해가 뒤따른다. 각 줄을 2발씩 맞히는 설계는 총 8발, 92.8 마나를 사용한다. 세 번째 적도 직접 피해 16에 후속 화상으로 HP 20을 넘길 수 있다.
- 범위 폭발로 여러 적을 묶어 처치하는 해법도 허용한다. 특정 룬 사용 자체를 성공 조건으로 삼지 않는다.

**판정과 피드백:** 12마리 전부 처치하면 성공한다. 사망 또는 플레이어 중단이면 종료한다. 마나 부족은 해당 실행 경로를 막는 기존 규칙을 사용하며 즉시 실패로 판정하지 않는다. 남아 있는 탄환·화상·예약 실행으로 목표를 달성할 수 있기 때문이다. 출격 전에는 `마나 100, 회복 없음, 12마리 전부 처치`, 전투 중에는 현재 마나와 남은 적을 표시한다. 결과에는 처치 수와 사용 마나를 보여줘 한 시전의 효율을 비교할 수 있게 한다.

### P2: 작은 마나통으로 빠르게 처치

**주고자 하는 경험:** 총 마나 공급은 충분해도 큰 비용을 한 번에 지불할 수 없다. 약한 실행을 연속으로 쓰거나 시간차를 둬, 낮은 최대 마나에 맞는 마법을 만든다.

**적 구성:** 0·2·4·6초에 각 6마리씩 총 24마리가 등장한다. 각 회차는 3마리 일렬 묶음 2개다. x는 240·290·340이고 y는 -60·60이다. 고정 위치는 시작 플레이어 기준이며 현재 플레이어를 따라 옮기지 않는다.

**첫 시도에서 드러날 문제:** 일반 발사로 개별 처치하면 48발이 필요하다. RAM 1의 쿨다운 0.28초에서 첫 발을 0초에 쏘더라도 마지막 발은 약 13.16초로 12초를 넘긴다. 효과 증폭 발사의 단일 실행 비용 11.2는 최대 마나 10보다 커서 회복 속도가 빨라도 실행할 수 없다.

**설계 방향과 해법 예시:**

- `구형(일반) → 발사 + 관통(C)`의 단일 비용 9.6은 마나통 안에 들어간다. 한 발의 직접 피해 10·9·8을 고려해 각 3마리 묶음에 3발씩, 총 24발을 맞히는 방향으로 설계한다. 화염 관통의 단일 비용 11.6은 마나통을 넘으므로 P2의 해법 예시로 사용하지 않는다.
- 회복량 100/s이면 9.6 마나 회복에 약 0.096초가 필요해 기존 쿨다운 사이에 다시 시전할 수 있다. 시전당 비용을 낮추면서 여러 적을 처리하는 것이 핵심이다.
- 비용 10의 폭발을 연속 사용하거나, 지연 후 다음 실행을 발생시키는 해법도 허용한다. 전체 그래프의 예상 총 비용이 10을 넘는다는 이유만으로 출격을 차단하지 않는다. 각 실행 노드에 도달할 때 마나를 지불하는 기존 의미를 유지한다.

**판정과 피드백:** 12초까지 24마리 전부 처치하면 성공한다. 사망, 시간 초과 또는 중단이면 종료한다. 마나 부족으로 중단된 노드는 현재 시도의 실패 원인 정보로 표시하며 전투 전체를 즉시 끝내지 않는다. 출격 전에는 `최대 마나 10, 회복 100/s, 12초, 24마리 전부 처치`, 결과에는 처치 수와 마나 부족으로 실행하지 못한 노드·비용을 표시한다. 자동 힌트로 정답 그래프를 제공하지 않는다.

### P3: 제한시간 내 목표 처치

**주고자 하는 경험:** 한 적을 확실히 잡는 설계에서 여러 적을 빠르게 처리하는 설계로 생각을 전환한다. 제한시간 안에서 처리량을 높이는 조합을 발견한다.

**적 구성:** 0·2·4·6·8·10·12초에 각 6마리씩 총 42마리가 등장한다. 매 회차의 위치는 시작 플레이어를 중심으로 반경 300, 각도 0·60·120·180·240·300도의 고정 원형 배치다. 42마리 이후 추가 스폰은 없다.

**첫 시도에서 드러날 문제:** 일반 발사로 목표 36마리를 개별 처치하면 최소 72발이 필요하다. RAM 1의 쿨다운 0.28초에서 마지막 발이 약 19.88초에 발생하므로 15초 목표에 맞지 않는다.

**설계 방향과 해법 예시:**

- 적을 같은 방향으로 모아 관통·폭발·잔류 효과로 한 번에 여러 적을 처리한다. 다중 발사로 다른 방향의 적을 함께 공격하는 해법도 허용한다.
- 일반 폭발의 기본 피해는 14다. 3마리씩 모아 각각 2회 맞히면 HP 20인 적을 처치할 수 있다. 36마리를 12묶음으로 처리하는 계산은 총 24회 폭발, 240 마나다. 15초 동안의 시작 마나와 회복량 합계는 최대 325로 총량상 가능하다.
- 실제 성공에는 적을 모으는 이동과 공격 시점이 필요하다. 위 계산은 명중·이동을 포함한 플레이 성공을 보장하는 수치가 아니다.

**판정과 피드백:** 15초까지 목표 적 36마리를 처치하면 즉시 성공하며 나머지 적의 생존 여부는 묻지 않는다. 사망, 시간 초과 또는 중단이면 종료한다. 출격 전에는 `15초, 36마리 처치`, 전투 중에는 `처치 수 / 36`과 남은 시간을 표시한다. 실패 결과에는 목표까지 부족했던 처치 수를 표시한다.

### P4: 작은 RAM으로 스테이지 클리어

**주고자 하는 경험:** 노드를 계속 추가하는 방식으로는 제한을 넘긴다. 중복·불필요한 노드를 제거하고 형태나 연결을 바꿔, 작은 설계로 같은 목표를 해결한다.

**적 구성:** 0·3·6·9초에 각 6마리씩 총 24마리가 등장한다. 회차별 묶음 중심은 (240, 0), (0, 240), (-240, 0), (0, -240)이다. 묶음 안 상대 좌표는 x=-25·25, y=-40·0·40의 2×3 배치다. 추가 스폰은 없다.

**첫 시도에서 드러날 문제:** 일반 발사로 개별 처치하면 48발이 필요해 최소 시전 시간만 약 13.16초다. 여러 효과를 붙여 처리량을 늘리려 해도 RAM 2를 넘기면 출격할 수 없다.

**설계 방향과 해법 예시:**

- 각 적을 따로 공격하는 발사를 가까운 적을 함께 맞히는 폭발로 바꾼다.
- `시작 조건 → 구형(일반) → 폭발`은 RAM 1이다. 묶음의 6마리가 범위에 함께 들어오게 조준해 2회씩 맞히면, 총 8회 폭발·80 마나로 24마리를 처치하는 방향을 만들 수 있다.
- 화염 폭발(RAM 2)처럼 직접 피해와 화상으로 처리하거나, 관통 발사(RAM 2)로 여러 적을 맞히는 대안도 허용한다. RAM을 반드시 2까지 사용할 필요는 없다.
- RAM은 배치한 전체 그래프를 대상으로 계산한다. 실행되지 않는 장식 노드도 용량에 포함하며 보유 재화로 용량을 늘려 제한을 우회할 수 없다.

**판정과 피드백:** 편집은 작업실 RAM 규칙으로 진행하며, 출격할 때만 퍼즐 RAM 2와 문법 적합성을 검사한다. RAM이 초과하면 `RAM 사용량 / 2`와 초과량을 표시하고 출격을 막으며 편집 상태를 유지한다. 적 24마리를 12초까지 전부 처치하면 성공한다. 사망, 시간 초과 또는 중단이면 종료한다. 결과에는 목표 달성 여부와 사용 RAM·처치 수·소요 시간을 표시한다.

### 공통 판정과 재설계

1. 마법 문법 오류나 RAM 초과는 출격 준비 실패로 처리한다. 제한시간은 전투를 시작한 0틱부터 계산하고 일시정지 중에는 흐르지 않는다.
2. 매 틱의 피해·처치를 반영한 뒤 HP가 0이면 사망을 우선한다. 살아 있다면 성공 조건을 확인하고, 성공하지 못했을 때 제한시간 초과를 확인한다. 따라서 생존 상태에서 마지막 처치와 시간 종료가 같은 틱이면 성공이다.
3. 종료 후에는 새 입력·스폰·마법 실행을 멈추고, 남은 개체·상태이상·예약을 정리한다. 성공·실패 결과는 한 번만 확정한다.
4. 결과의 기존 `재도전`은 같은 퍼즐과 현재 설계를 초기 조건으로 다시 시작한다. 기존 `마법 강화`는 일반 작업실의 현재 마법을 열며, 수정 후 선택했던 퍼즐로 다시 출격할 때 조건을 검사한다. 마법 수정 중에는 전투시간이 진행되지 않는다.
5. 마나 0 자체는 패배 조건이 아니다. P1은 플레이어가 시전 실패·남은 목표를 보고 중단 후 재설계할 수 있게 한다. P2~P4는 목표 미달 시 제한시간에 종료한다.

### 기존 구조와의 연결

기존 메뉴·출격·편집·미션·결과 View와 `MissionRun`·`RuneSimulation`의 입력, 마법, 적 이동, 충돌, 상태이상 계산을 재사용한다. 퍼즐별 고정 설정·유한 스폰·목표 판정·출격 검사·보상 없는 종료를 기존 경로에 연결한다.

| 연결 대상 | 구현 시 반영할 내용 |
|---|---|
| 출격·편집 세션 | 일반 스테이지와 퍼즐 선택은 출격 대상으로만 구분한다. 작업실 편집을 유지하고 출격할 때 현재 마법을 퍼즐 조건으로 별도 검증한다. |
| 전투 생성 | 시작·최대 마나와 회복량을 명시적으로 전달한다. 현재 생성자는 회복량 0을 기본값으로 대체하므로, P1의 0/s와 설정 생략을 구분하도록 확장해야 한다. |
| 스폰·목표 | 일반 전투의 무한 스폰 대신 퍼즐에 명시된 유한 배치를 사용한다. 네 퍼즐의 모든 적을 목표 집계 대상으로 삼고, 전부 처치와 목표 수 처치를 구분한다. 일반 전투의 기존 `IsKillTarget` 집계를 그대로 쓰면 웨이브 적이 제외될 수 있어 확인이 필요하다. |
| 전투 종료 | 일반 스테이지에서도 퍼즐 제한시간을 판정할 수 있게 한다. 현재 일반 전투는 목표 처치 수, 보스 전투는 보스 처치·제한시간을 사용하므로 퍼즐 조건을 별도로 전달해야 한다. |
| 결과·복귀 | 결과·일시정지·재도전 UI를 공유하고 퍼즐 조건과 결과 수치를 표시한다. 일반 전투 정산 호출을 통해 보상·진행도가 변경되지 않도록 퍼즐 종료 경로를 구분한다. |

### 기획 완료와 후속 확인

- 네 가지 경험에 대응하는 퍼즐만 정의했으며 초기 상태, 적 구성, 성공·실패, 재설계·재도전 기준을 명시했다.
- 현재 룬의 기본 비용·피해·RAM·쿨다운으로 각 퍼즐의 설계 방향을 설명했다. 참고 기준은 발사 비용 8·피해 10, 폭발 비용 10·피해 14, 관통 비용 배율 1.2, 화상 3 DPS·3초, 쿨다운 `0.25 + RAM × 0.03`이다.

- 이번 문서 작성에서는 Unity 실행이나 실제 퍼즐 클리어를 검증하지 않았다. 현재 상태는 기획 구체화 완료이며 구현·플레이 검증은 후속 작업이다.

### 퍼즐 조건과 마법 편집 분리: 2026-10-10

- 전투 메뉴는 출격할 전투 종류와 퍼즐 번호만 선택한다. 보관함·활성 마법·편집 이력을 전환하거나 초기화하지 않는다.
- 마법 편집·컴파일·장착·튜토리얼·성장 표시와 시험 도크는 항상 기존 작업실 규칙을 사용한다. 퍼즐 선택으로 추가 RAM 제한, 룬 제공, 마나 변경 또는 도크 적응 제한을 적용하지 않는다.
- 출격할 때 현재 마법을 선택한 퍼즐의 RAM·마나 조건과 기존 문법·해금·소지량으로 별도 컴파일한다. 문법 오류나 RAM 초과는 출격을 막고 이유를 표시한다. 예상 총 마나 비용은 기존처럼 경고이며 실행 노드의 마나 지불 규칙을 유지한다.
- 이전 퍼즐 전용 저장 항목은 일반 보관함으로 이관한다. 기존 일반 마법을 덮어쓰지 않으며, 보관함 한도나 서로 다른 설계의 ID 충돌로 옮기지 못한 항목은 이전 저장 항목에 남겨 보존한다.
- Unity 6000.3.22f1 최종 컴파일이 오류 없이 통과했다. 메모리 사본에서 P4 선택 중 RAM을 2→3으로 늘리는 편집과 작업실 컴파일이 허용됐고, 출격 검사만 `3 / 2 (+1)`로 거부했다. 같은 RAM 3 마법은 P1·일반 전투 검사에서 통과했으며 RAM 2로 줄이면 P4도 통과했다.
- 퍼즐 출격 검사 후에도 편집 컴파일 결과가 동일하고, 퍼즐 변경 후 되돌리기 이력이 유지됐다. 잘못된 Core 문법은 출격을 거부했다. 검사 사본은 사용자 저장 파일에 기록하지 않았다.
- 실제 메뉴에서 P2를 선택하고 편집기로 돌아와도 작업실 RAM 6·기존 최대 마나·도크 마나 회복이 유지됐다. 일반·퍼즐 메뉴 왕복에서도 같은 그래프 객체와 활성 마법을 사용했다.
- 실제 출격 버튼으로 RAM 2 마법이 P4에 진입하고 HP 100·마나 100·회복 15/s를 적용했다. 중단 후 P4 편집 화면으로 복귀했으며 이 과정에서 저장 데이터가 동일했다.
