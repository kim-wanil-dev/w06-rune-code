# 게임 도움말 구현 계획

## 1. 목표와 범위

작업실과 스테이지 선택 화면에서 게임 규칙을 확인할 수 있는 도움말 팝업을 제공한다. 두 화면의 스크랩 수량 표시와 설정 버튼 사이에 도움말 버튼을 배치하고, 같은 팝업을 연다.

디자인은 [game_help_ui.html](game_help_ui.html)의 상단 제목, 왼쪽 목차, 오른쪽 설명 구조를 참고한다. Unity의 uGUI와 TextMesh Pro로 구성하고, 색상과 버튼·패널 표현은 현재 게임 UI에 맞춘다.

메뉴 제목과 설명은 외부 JSON으로 관리한다. HTML에 들어 있는 예시 규칙은 현재 게임에 맞는 설명으로 작성한다.

## 2. 화면 구성과 설정

### 진입 버튼

- `WorkshopScreen`의 헤더에 `도움말` 버튼을 추가한다.
- 스크랩 수량 표시 → 도움말 → 설정 순서로 배치한다.
- 작업실과 스테이지 선택 상태에서 모두 버튼을 표시한다.
- 도움말을 열거나 닫아도 현재 탭, 선택 스테이지, 마법 설계는 유지한다.

### 도움말 팝업

- 기준 해상도는 기존 UI와 같은 1280×720이다.
- 팝업은 중앙에 배치하고, 초기 크기는 약 1100×620으로 잡아 창 바깥에 클릭할 여백을 남긴다.
- 상단에 `게임 도움말` 제목과 짧은 안내 문구, 우측에 닫기 버튼을 배치한다.
- 본문은 왼쪽 목차와 오른쪽 설명의 두 영역으로 나눈다. 목차 너비는 전체의 약 25%를 기준으로 조정한다.
- 왼쪽에는 항목 번호, 제목, 선택 표시, 전체 항목 수를 표시한다.
- 오른쪽에는 선택한 항목의 제목과 본문을 표시한다.
- 목차와 본문은 각각 독립적인 세로 ScrollRect를 사용한다.

현재 게임의 패널 배경, 테두리, 기본 텍스트, 보조 텍스트, 강조색을 사용한다. 기존 버튼·패널 자산과 게임에서 사용하는 TMP 폰트 설정을 기준으로 맞추고, 새 팝업 프리팹에서 색상과 여백을 조정할 수 있게 한다.

## 3. 외부 데이터

### 자료형

| 자료형 | 읽기용 프로퍼티 | 저장 필드 | 용도 |
| --- | --- | --- | --- |
| `EncyclopediaData` | `Entries` | `_entries` | 항목 배열 |
| `EncyclopediaEntry` | `Title` | `_title` | 목차 이름과 설명 제목 |
| `EncyclopediaEntry` | `Body` | `_body` | 설명 본문 |

제목과 본문 두 필드로 구성한다. 배열 순서가 목차 순서가 되며, 항목 번호와 전체 개수는 배열에서 계산한다.

본문의 문단은 줄바꿈으로 구분한다. 소제목과 강조는 필요한 범위에서 TMP의 굵게·크기 서식으로 표현하고, 글자 색상은 UI 설정에서 관리한다.

### 파일과 읽기 방식

데이터 파일은 `Assets/RuneCode/Resources/RuneCode/encyclopedia.json`에 둔다.

```json
{
  "_entries": [
    {
      "_title": "게임 기본 흐름",
      "_body": "작업실에서 마법을 설계하고 스테이지를 선택해 출격합니다.\n\n전투에서 얻은 스크랩으로 강화를 진행합니다."
    },
    {
      "_title": "마법 설계",
      "_body": "룬 노드를 배치하고 포트를 연결하여 마법을 설계합니다."
    }
  ]
}
```

위 내용은 데이터 형식의 예시다. 실제 설명은 현재 코드와 게임 내 표시를 확인하여 작성한다. 초기 목차는 게임 기본 흐름, 기본 조작, 룬 설계, 스크랩과 RAM, 강화, 스테이지와 전투 결과를 기준으로 구성한다.

`WorkshopPresenter`가 처음 도움말을 열 때 `Resources.Load<TextAsset>`과 `JsonUtility`로 데이터를 읽고 보관한다. 읽은 데이터는 팝업의 `Configure`에 전달한다. Resources 데이터이므로 게임 빌드에 포함되며, 배포 후 파일을 별도로 교체하는 로딩 방식은 이번 범위에 포함하지 않는다.

## 4. 표시와 닫기 동작

### 열기와 항목 선택

1. 도움말 버튼을 누르면 데이터를 준비하고 `UIManager.OpenPopup<EncyclopediaPopup>()`으로 팝업을 연다.
2. 목차는 최초 데이터 전달 시 구성하고 이후 다시 사용할 수 있게 보관한다.
3. 팝업을 열 때 첫 항목을 선택하고 좌우 스크롤을 맨 위로 초기화한다.
4. 목차를 누르면 해당 항목의 제목·본문과 선택 표시를 갱신한다.
5. 항목 전환 시 오른쪽 스크롤만 맨 위로 이동하고 왼쪽 스크롤 위치는 유지한다.

### 닫기와 입력 처리

- 닫기 버튼은 `UiPopup`의 공통 닫기 처리를 사용한다.
- 창 바깥 전체를 덮는 배경 버튼은 `Close()`에 연결한다.
- 팝업 내부 패널은 Raycast를 받아 내부 빈 공간을 클릭해도 배경 버튼이 눌리지 않게 한다.
- 목차 선택과 스크롤 조작으로 팝업이 닫히지 않게 한다.
- 기존 `UiPopup`의 Esc 닫기 동작을 유지한다.
- 팝업 배경이 뒤쪽 UI의 클릭을 막고, 편집 단축키·도크 입력은 기존 `UIManager.IsPopupOpen` 경계를 사용한다.

데이터가 없거나 항목 배열이 비어 있으면 빈 항목을 선택하지 않고 안내 문구를 표시한다. 이 상태에서도 닫기 동작은 사용할 수 있게 한다.

## 5. 연결 대상과 변경 파일

| 파일 | 변경 내용 |
| --- | --- |
| `Assets/RuneCode/UI/Workshop/WorkshopScreen.cs` | 도움말 버튼 참조와 클릭 이벤트 추가 |
| `Assets/RuneCode/UI/Workshop/WorkshopPresenter.cs` | 클릭 이벤트 연결·해제, 최초 데이터 읽기, 팝업 열기 |
| `Assets/RuneCode/Resources/RuneCode/UI/WorkshopScreen.prefab` | 두 화면에서 사용할 헤더 버튼 배치·연결 |
| `Assets/RuneCode/Core/Data/EncyclopediaData.cs` | 전체 목록과 제목·본문 데이터 타입 추가 |
| `Assets/RuneCode/Resources/RuneCode/encyclopedia.json` | 실제 게임 도움말 내용 작성 |
| `Assets/RuneCode/UI/Workshop/EncyclopediaPopup.cs` | 데이터 표시, 목차 선택, 스크롤 초기화, 바깥 클릭 연결 |
| `Assets/RuneCode/Resources/RuneCode/UI/EncyclopediaPopup.prefab` | 팝업 레이아웃, 닫기·배경 버튼, 텍스트·스크롤 참조 |
| `Assets/RuneCode/Resources/RuneCode/UI/Elements/EncyclopediaRow.prefab` | 도움말 목차 행과 선택 표시 |

새 팝업은 `UiPopup`을 상속하고 기존 `UIManager`의 생성·표시·재사용 흐름을 따른다. 화면마다 별도 팝업을 만들지 않는다.

목차 행은 기존 `UiRow`를 사용하고 선택 표시는 `TabButton`과 `UiStateVisual`을 우선 재사용한다. 데이터 로딩은 Presenter가 담당하고, 팝업은 전달받은 데이터를 표시하고 선택 상태와 스크롤을 관리한다.

## 6. 구현 순서

1. 제목·본문 데이터 타입과 JSON을 작성한다.
2. 목차 행과 도움말 팝업 프리팹을 구성하고 게임 UI 색상·폰트를 맞춘다.
3. 팝업에 데이터 표시, 선택 전환, 독립 스크롤, 닫기 동작을 연결한다.
4. WorkshopScreen 헤더에 도움말 버튼을 추가하고 Presenter의 클릭 이벤트와 연결한다.
5. 현재 게임 동작을 기준으로 설명 내용을 확인하고 Unity에서 완료 기준을 검증한다.

## 7. 완료 기준

- 작업실과 스테이지 선택에서 스크랩 수량과 설정 사이에 도움말 버튼이 표시된다.
- 두 화면에서 같은 도움말 팝업이 열리며, HTML의 좌우 구성과 게임 UI의 색상·폰트가 적용된다.
- JSON 항목 추가·삭제·순서 변경이 목차에 반영되고 선택한 제목·본문이 일치한다.
- 긴 목차와 본문이 독립적으로 스크롤되고, 항목 전환 시 오른쪽만 맨 위로 이동한다.
- 닫기 버튼, 창 바깥 클릭, Esc로 닫히며 내부 클릭과 스크롤로는 닫히지 않는다.
- 팝업이 열린 동안 뒤쪽 UI 클릭과 편집 단축키·도크 입력이 차단된다.
- 반복해서 열고 닫아도 버튼 이벤트가 중복 실행되지 않는다.
- 닫은 뒤 현재 탭, 선택 스테이지, 마법 설계가 유지된다.
- 데이터가 없거나 빈 목록일 때 안내가 표시되고 팝업을 닫을 수 있다.
- 관련 코드가 컴파일되고 팝업·목차·버튼·스크롤의 자산 참조에 누락이 없다.

## 8. 구현 및 검증 기록

2026-10-12: 위 연결 대상의 데이터·JSON·팝업·목차 프리팹과 공통 헤더 버튼을 구현했다. 목차 행은 기존 TabButton의 Variant에 UiRow를 연결했고, 기존 패널·버튼 스프라이트와 TMP 폰트를 사용한다. 팝업을 다시 열면 첫 항목과 양쪽 스크롤을 초기화하고 항목을 전환하면 본문 스크롤만 초기화한다. 데이터 누락·빈 목록·JSON 읽기 실패 시 안내를 표시한다.

도크의 포인터 조준·클릭 시전·R 초기화는 기존 팝업 차단 경계를 적용했다. 기존 자동 시험 진행은 유지한다. 원본 설정 버튼의 배치·참조는 유지하고 스크랩 표시 영역의 너비를 줄여 그 사이에 도움말 버튼을 배치했다.

### 완료한 검증

- 원본 Editor를 유지한 채 임시 프로젝트 복사본을 Unity 6000.3.22f1에서 컴파일하고 Unity Prefab API로 자산을 생성했다. 최종 실행 종료 코드는 0이다.
- 팝업·목차 행·작업실 프리팹의 Missing Script가 0이며 팝업의 닫기·배경·목차·본문·텍스트·행 참조가 연결되어 있음을 확인했다.
- Unity 카메라로 공통 헤더와 도움말의 기본 항목·긴 기본 조작 설명을 렌더링해 글꼴·색상·선택 표시·배치·본문 클리핑을 확인했다. 긴 본문 콘텐츠 높이는 약 960px이며 본문 뷰포트는 496px이다.
- 원본 작업실 프리팹이 준비 당시 내용과 같은지 확인한 뒤 생성 자산과 .meta만 반영했다. 기존 프리팹 변경은 도움말 버튼 추가·참조와 스크랩 표시 영역 너비 조정으로 제한했다.
- JSON의 여섯 항목과 현재 코드의 전투 조작·스크랩/RAM·강화·전투 정산 규칙을 확인했다.

### 남은 Play 확인

원본 프로젝트의 Play 입력 검증과 게임 빌드는 실행하지 않았다. 추가 Inspector 연결은 필요하지 않다. `Assets/Scenes/Boot.unity`를 열고 다음 항목을 확인한다.

1. 작업실의 룬 설계·강화 트리와 스테이지 선택 각각에서 헤더 도움말 버튼을 눌러 같은 팝업이 열리는지 확인한다.
2. 본문을 아래로 스크롤한 뒤 항목을 바꿔 오른쪽만 초기화되는지 확인한다. 목차가 길어지는 경우에는 JSON에 항목을 추가한 뒤 Play를 다시 시작해 왼쪽 독립 스크롤도 확인한다.
3. 내부 빈 공간·목차·스크롤 조작은 창을 유지하고 닫기 버튼·바깥 클릭·Esc는 창을 닫는지 확인한다.
4. 팝업이 열린 동안 편집 단축키·도크 클릭·조준·R 초기화가 차단되고, 닫은 뒤 현재 탭·선택 스테이지·마법 설계가 유지되는지 확인한다.
5. 반복 열기·닫기에서 선택 표시와 버튼 실행이 중복되지 않는지 확인한다. 별도 작업 복사본에서 빈 JSON 목록 또는 데이터 누락 상태도 확인한다.
