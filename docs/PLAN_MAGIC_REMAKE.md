## 1. 목표와 구현 순서

### 이번 작업의 PoC 범위

사용자 요청에 따라 아래 경로만 먼저 구현한다. P0~P7 전체 요구사항의 완료를 의미하지 않는다. T-06 행동·방어 트리거와 평타·패링·방어 마법은 이번 범위에서 제외한다. 기존 이동·대시는 유지한다.

| 범위 | 구현 내용 |
|---|---|
| 입력 | 좌클릭 1회 즉시 시전, Root의 홀드 반복 옵션, 정지 차징·해제 시전, 홀드 유지·해제 취소 |
| 형태 | Vector 투사체/빔, Construct 낙하 가시, Wall 고정 장벽/이동 파동, Tether 적 연결, Infusion 적 표식, Domain 원형 영역 |
| 사건 | 생성·적중·사거리 끝·지형 충돌·착지·종료, 경과·주기, 누적 실제 피해·적중 횟수, 상태 부여·처치·표식 대상 사망, 연결 단절, 영역 진입·이탈 |
| 유한 정책 | 1회/개체당/횟수 제한, 최소 간격. Infusion의 사망 또는 시간 중 먼저 발생한 사건 1회 |
| 제약·보상 | 최대 EN 50% 추가 지불→피해 2.5배/반경 3배, 동결 소비→피해 2배, HP 30% 이하→피해 1.5배 |
| 적용 범위 | 바로 다음 형태 또는 Root 첫 단계에서 시작하는 시전 전체. 중첩 강화와 임의 구간 선택은 제외 |
| 작성·확인 | 사건 포트, 트리거/제약 인스펙터, 편집·복제·Undo/Redo, 도크 사건 기록, 저장하지 않는 4개 PoC 미리보기 |
| 호환 | 기존 v1 실행/RC1 유지, 새 그래프 v2/RC2, 저장 v3 및 v1/v2 읽기. 기존 설계를 자동 치환하지 않음 |

PoC에서는 일반 무기·시전자 Aura, 자유 곡선/임의 구조체, 파괴 가능한 결계 핵, AllOfGroup·일반 FirstOf, 임의 구간 강화, 강화 중첩, HP/EN 변화 감시·스택 임계값, 상태 제거·환경 반응, 방어막 파괴, 지속 피해의 처치 계보 전파를 후속 작업으로 남긴다. 신규 해금 가격과 전투 밸런스의 완성도도 이번 검증 대상이 아니다.

최소 확인 경로는 `Vector → 적중 → 자원 제약 → Domain`, `Beam → 개체당 적중 → Infusion → 사망/시간 → Construct`, `Vector → Tether → 2초 유지 → Wall`, `차징 → Construct → 착지 → Wave`다. 원래 P0~P7은 이 경로를 확장할 때의 후속 계획으로 유지한다.

한 활성 그래프 안의 형태가 사건·대상·위치를 전달하고, 제약/지불에 성공한 구간만 강화되어 후속 실행되는 구조를 완성한다. 기본 시전 입력은 사용자 결정대로 마우스 클릭·홀드로 통일한다.

```text
P0 기준·수치표
  → P1 그래프/카탈로그/호환 형식
  → P2 사건·예약·실행 수명·지불
  → P3 클릭·차징·평타 + Vector/Construct 세로 구현
  → P4 Wall/Tether/Infusion/Domain + 집계·경쟁
  → P5 제약·강화·나머지 트리거
  → P6 전체 편집·도크·콘텐츠·저장 연결
  → P7 통합 검증·밸런스·빌드
```

각 단계는 자신의 종료 조건과 관측 결과를 기록한 뒤 다음 단계로 진행한다. 기능 전체를 구현하기 전에 입력→그래프→사건→후속→비용→표시가 연결되는 작은 경로를 먼저 완성한다. 단계 번호는 작업 의존성이며 기간 추정이 아니다.

## 3. P0 — 구현 기준과 수치표 기록

**입력:** 현재 PRD, 기존 수식·저장·전투·편집 경로. **대상 요구:** 전체 기준, I, R, S.

### 작업

1. 현재 활성 설계·플레이어 진행·기존 도크 결과를 보존할 기준 자료를 기록한다. 기존 검증 문서의 수치가 현재 버전과 같은 조건인지 구분한다.
2. 여섯 형태의 최소 변형 목록과 사건 공급표, 트리거 관측 범위, 위치/방향 선택표를 PRD와 대조한다.
3. 신규 기본 피해·EN·유지 비용·RAM·수명·해금 가격·평타 범위/쿨다운의 초기 수치표를 작성한다. 도크용 고급 템플릿과 일반 전투 해금을 구분한다.
4. 기본 입력은 클릭/홀드로 확정해 기록한다. I-05~07의 우클릭/E·무기 모드 세부 제안과 처형 정책·승격 비용은 PRD 제안값으로 시작하되 사용자 변경 요청이 있으면 해당 항목만 반영한다.
5. 새 저장/공유 형식과 legacy 실행·승격 경로를 문서화한다. 이전 설계를 임의로 새형태로 치환하지 않는다.

**종료 조건:** 미정 수치의 소유 위치와 최초값, 입력 안내, 이전 자료가 정해져 다음 단계에서 상반된 비용/이벤트 모델을 만들지 않는다. 실제 착수 기록은 PROGRESS의 별도 리메이크 구간에 남긴다.

## 4. P1 — 그래프·정의·컴파일·호환 기반

**의존:** P0. **대상 요구:** G, C-01~02, S-01~04, U-03~04.

### 작업

1. GraphNode/GraphEdge의 기존 ID·좌표·파라미터 구조를 확장하고 새정보의 복제/직렬화 보존을 연결한다.
2. 실행/사건/부착 포트를 구분하고 여섯 계열·변형·트리거·제약 강화 정의를 카탈로그에 추가한다.
3. 컨텍스트 없는 대상 요구, 공급하지 않는 사건, 무효 구간, 실행 순환, 무제한 정책을 컴파일 단계에서 검출한다.
4. 그룹 진입/멤버·강화 범위와 AllOfGroup/FirstOf의 참조를 해석한다. RAM 합산·부착 호환·상한 추정을 새모델에 연결한다.
5. 그래프v2/RC2와 이전v1/RC1의 로딩·컴파일 경로를 구분한다. 기존 검증 오류코드는 의미를 유지하며 새오류는 한국어 메시지를 추가한다.

**확인:** 저장/공유 왕복, 구간 참조 복제, 잘못된 포트/대상/참조/버전 오류, 기존 O1~O7 조건의 호환 수치와 의미를 실행 가능한 기존 도구로 관측한다.

**종료 조건:** 새그래프를 표현·검증하고 컴파일 결과로 사건/범위/비용 정보를 전달한다. 기존 그래프 로드와 실행을 계속 사용할 수 있다.

## 5. P2 — 사건·예약·수명·지불의 공통 실행

**의존:** P1. **대상 요구:** G-04~07, T, C-03~07, R, 8절.

### 작업

1. 기존 시전/노드/개체 식별을 사건 계보에 연결하고 발생 위치·대상·마지막 위치·종료 원인을 보존한다.
2. 현재 예약 실행을 소유자·시전·취소 원인까지 확장한다. 트리거 관측/대기와 유지 상태가 어떤 객체에 속하는지 명시한다.
3. 생성/종료/적중/사망 기본 사건과 안정적인 같은 틱 순서를 연결한다. 마지막 정보 확보 후 대상 제거를 처리한다.
4. 대상별1회·횟수·간격·임계값 진입·관측 범위와 FirstOf/AllOfGroup의 공통 동작을 연결한다.
5. 단계별 원자적 EN 지불과 기본 범위 보상 전달을 연결한다. legacy 그래프의 기존 선지불은 별도 호환 규칙으로 유지한다.
6. 깊이·예약·개체·활성 관측·집계·틱당 실행 상한과 생략 이유를 수집한다.
7. 전투 종료/리셋/교체/사망·취소에서 관측·예약·집계와 임시 상태를 정리한다.

**확인:** 동일 사건1회, 같은 틱 경쟁 승자, 다른 시전 집계 분리, EN70/59 지불 예시, 취소 뒤 후속 없음, 같은 입력/시드 사건 순서 일치.

**종료 조건:** 한 형태가 낸 사건으로 후속이 한정된 횟수만 실행되며, 실패/취소/지불이 관측 가능하다. 그래프 확장이 실행 무한 증가로 이어지지 않는다.

## 6. P3 — 입력과 Vector/Construct의 첫 전체 경로

**의존:** P2. **대상 요구:** I, F-01~02, U-05~08 일부.

### 작업

1. 포인터 자동 시전을 좌클릭 누름/홀드/해제 이벤트로 대체한다. 기존 이동·조준·대시·일시정지와 포커스/영역 경계를 연결한다.
2. 즉시·차징·유지 모드와 우클릭 재시전 입력을 구현한다. InputSystem 입력을 렌더 프레임에서 수집하고 60Hz에서 중복 누름 없이 소비한다.
3. Vector 직선/곡선/광선의 경로·관통·사거리·대상별 간격과 종료 원인을 연결한다.
4. Construct의 검/창/망치/가시, 휘두르기/찌르기/2D 낙하·착지와 기본 무기 캐리어 평타를 연결한다.
5. 기존 uGUI 그림으로 경로·방향·공격 궤적·준비 상태를 구별한다. 최소 편집기로 클릭→Vector 적중→지연→Construct 가시를 작성한다.

**확인:** 클릭 수와 시전 수 일치, 최소 차징 미달/최대/해제1회, 홀드 종료, 평타 실제 적중, 지형 충돌/거리 소진 분리, 위치·방향 선택 차이, 준비/발사 EN.

**종료 조건:** 실제 입력→작성 그래프→두 형태→후속 사건→비용→도크 표시가 한 경로에서 연결된다. 입력 변경 안내를 갱신한다.

## 7. P4 — 나머지 형태와 대표 복합 사건

**의존:** P3. **대상 요구:** F-03~06, T-07~10, I-06~09.

### 작업

1. Wall의 적/투사체 차단·내구도·핵·폐곡선과 Wave의 이동/방사·밀기를 기존 맵 판정에 연결한다.
2. Tether의 양끝 참조·거리/시야·유지·구속·당기기·단절 원인을 연결한다.
3. Infusion의 대상별 소유·스택·시간·주입된 캐리어 적중/사망 사건을 연결한다. 그래프 갱신과 별개인 주입 수명을 보존한다.
4. Domain의 진입/이탈/중심 추적/고정 전환·주기 피해·이동 규칙 및 정상/강제 종료를 연결한다.
5. 캐리어 방어의 실제 차단에 패링 창을 연결한다. 대시 방향과 재시전은 살아 있는 모듈의 동작으로 전달한다.
6. 네 끝점→폐곡선 장벽 집계, 대상별 사망/3초 경쟁을 형태 사건과 연결한다.
7. 불안정 마력·출혈·기절 프로필을 상태 카탈로그·조건·표시와 연결하고 기존 상태의 재부여/면역을 보존한다.

**확인:** 장벽이 화면뿐 아니라 실제 이동/투사체를 막음, 겹침 보정, 연결이 끊기면 유지 타이머 종료, 적/아군 주입 대상 혼동 없음, 상태 만료 후 규칙 제거, 집계/경쟁 각각1회.

**종료 조건:** 여섯 형태가 모두 실행되고 A/B/C 템플릿의 형태·사건 경로가 성립한다. 이 단계에서는 고배율 수치 밸런스 완료를 요구하지 않는다.

## 8. P5 — 제약 보상과 수치/상태/행동 트리거 완성

**의존:** P4. **대상 요구:** T-02~06, C, R, 강화 프로필.

### 작업

1. 전체/다음 형태/명시 구간 제약·보상을 작성 정보와 실행 범위에 연결한다.
2. 거리·정지·HP/EN·상태/중첩·대상 종류·핵 유지·소모·재사용 제약을 실제 조건으로 연결한다.
3. 집중·근접 구속·주입 공명·자원 교환·노출 결계·처치 회수·열충격 프로필을 연결한다.
4. 비용 부족/대상 없음/유지 위반/모듈 교체를 실패 이유로 전달하고 보상 경계 누출·대가 중복 지불을 방지한다.
5. 누적 실제 피해/차단·HP/EN 임계값·상태 필터/변화·처치/대상 사망·대시/패링/재시전의 모든 계열을 완료한다.
   적의 선택적 보호막 수치와 소진 사건을 추가하고, 도크에서 실제 소진을 확인한다. 기존 이지스 전방 감쇠와 혼동하지 않는다.
6. 강화와 일반 수식의 합성, 조건 중복, 현재EN 비율 지불 최소값, 방어 우회/보스 처형 정책을 연결한다.
7. 기존 적응 기능에 새형태 태그를 연결하되 현재 일반 단계의 적응 활성 설정을 보존한다.

**확인:** 조건별 성공/미충족/대가 부족, 유지 취소, 강화 범위 분리, 실제 비용 환급 상한, 초기화 후 사용자 입력 필요, 상태 소모1회, 보스/방패/무적/릴레이 경계.

**종료 조건:** 대가를 실제 지불한 범위에서만 표시된 강화가 적용된다. 조건 또는 단순 트리거를 늘려 무료·무제한 보상을 얻지 않는다.

## 9. P6 — 작성 경험·콘텐츠·저장·공유 통합

**의존:** P5. **대상 요구:** U, S, 대표 시나리오.

### 작업

1. 팔레트·사건 선택·위치/방향·트리거 반복/경쟁/집계·구간 경계·제약/대가/보상 인스펙터를 완성한다.
2. Undo/Redo·복사/붙여넣기·ID 재연결·한국어·오류 포커스·미지원 수식 경고를 전경로에 연결한다.
3. 도크에서 사건 계보·대기·실패·실제 지불·생략 이유를 표시한다. 전투에서 입력 역할·차징/유지·재시전 가능 상태를 표시한다.
4. 대표 A/B/C와 순서를 뒤집은 짧은 예시를 정식 콘텐츠로 작성한다. 단순 시작 Vector 템플릿과 도크 샌드박스 접근을 연결한다.
5. 기존 벤치·해금과 신규 수치표를 연결하고 기존 구매 이력·진행을 보존한다.
6. 저장v3 이전, 기존설계 보관/실행/승격 미리보기, RC1/RC2 공유를 실제 앱 흐름에서 완료한다.
7. 손상/알 수 없는 버전 복구·원본 보존을 확인하고 입력/설계 튜토리얼·README를 갱신한다.

**확인:** 편집기에서 직접 작성→도크→출격, 저장 재로드·공유 왕복·승격 취소, 기존 사용자 성장/해금/활성 설계 보존, UI 입력 중 전투 사건 없음.

**종료 조건:** PRD 기능을 코드 직호출 없이 사용자가 작성·실행·확인할 수 있다. 초기 콘텐츠와 기존 진행을 모두 사용할 수 있다.

## 10. P7 — 통합 확인·수치 조정·배포

**의존:** P6. **대상 요구:** PRD A-01~14 전체.

### 검증 순서

1. Unity 컴파일 결과와 연결된 PoC 장면의 참조·글꼴·그림·입력을 확인한다.
2. PRD 완료 기준 A-01~13을 기존 공개 API/SimulationCli/도크/수동 플레이로 관측한다. 검증용 테스트 코드·프레임워크·전용 테스트 자산은 추가하지 않는다.
3. A/B/C를 실제 편집기로 작성해 수동 입력으로 실행한다. 평타, 실제 차징 취소, 패링, 네 끝점 감옥과 사망/시간 경쟁을 화면과 실행 기록에서 대조한다.
4. 전투 종료·사망·리셋·교체·영역 밖 입력·포커스 상실·재활성화를 확인한다. 원본 사용자 저장은 실험의 보상/진행으로 바뀌지 않도록 별도 검증 경로를 사용한다.
5. 기준 장치와 시나리오를 기록하고 CPU 틱 p95·화면 FPS·개체/관측 수·생략 횟수·할당을 분리 측정한다. 실패한 제한/성능 원인에 해당하는 범위만 수정한다.
6. 제약 준비시간 대비 피해/구속/범위·EN 소모와 보상 리턴을 플레이로 조정한다. 수치 변경은 데이터와 수치표에 함께 기록한다.
7. 기존 도크/진행/정산·시전 legacy/저장·공유의 보존 기준을 확인한다.
8. 새 배포 경로로 Windows x64 빌드 후 실제 Player 입력·도크·템플릿·저장·종료를 확인한다. 이전 빌드 결과를 보존한다.

**종료 조건:** 완료 기준 결과·실제 컴파일/실행/빌드·측정 범위·남은 문제를 기록한다. 기능 일부가 미연결이면 전체 리메이크 완료로 표시하지 않는다.
