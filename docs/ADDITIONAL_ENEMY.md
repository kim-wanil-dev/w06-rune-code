# 추가할 적들

1. 자폭 씨앗
핵심: 자폭씨앗이 죽을 때, 주변에 광역 피해를 준다. 이 피해는 플레이어 뿐만 아니라, 적들도 피해를 입는다.
2. 초침 저격수
핵심: 센트리보다 위협적인 적. 1초 플레이어를 향해 조준하는 점멸하는 붉은색 반투명한 레이저를 겨냥한뒤, 0.1초뒤 마지막 레이저 경로를 지나가는 매우 빠른 투사체를 발사한다. 
3. 원형 보호막 적
핵심: 이 적을 처치하기 위해선 원형 보호막 안쪽으로 들어와야 한다. 플레이어의 투사체는 원형 보호막에 부딧치면 사라진다. 차후 기획에 따라 onHit가 동작할 수 있다.
    1. 원형 보호막 적 근접
        - 스카우트처럼 플레이어에게 근접해 피해를 주려는 적이다. 원형 보호막을 가지고 있다.
    2. 원형 보호막 적 원거리
        - 센트리처럼 원거리 공격을 한다. 원형 보호막을 가지고 있다.
4. 캐리어
특정 적을 생성하는 적. 프리팹으로 제작하되,  인스펙터에서 생성할 적들을 집어넣을 수 있고, 생성 주기, 1회 생성에 몇마리 생성 같은 걸 설정할 수 있다.
    1. 인터셉터
        플레이어 주위를 움직이며 공격하는 적이다. 1초 움직이고, 느린 원거리 탄으로 공격하면서 0.2초 정지 한뒤, 행동을 반복한다. 

## 6종 적 제작 계획

작성일: 2026-10-10. 상태: 6종 구현·Prefab 연결 완료, 검증 결과는 10절에 기록.

위의 원본 아이디어를 바탕으로 자폭 씨앗, 초침 저격수, 원형 보호막 근접형, 원형 보호막 원거리형, 캐리어, 인터셉터를 제작한다. 제작 순서는 적 정의 → 행동 확장 → 외형·Prefab 연결 → 등장 편성·보상 연결 → 핵심 동작 검증이다.

### 1. 목표와 확정된 동작

- 기존 적 디자인 표의 `id / 이름 / HP / 이동 / 공격·특성 / 보상` 양식을 사용한다. 외형은 현재의 도형 몸체, 어두운 중심부, 체력 막대, 상태 아이콘을 이어 쓴다.
- 자폭 씨앗은 사망할 때 주변 플레이어와 적 모두에게 범위 피해를 준다.
- 초침 저격수는 1초 동안 플레이어를 따라 조준하는 붉은 반투명 점멸 레이저를 보여 준다. 이후 조준을 고정하고 0.1초 뒤 마지막 레이저 경로로 고속 탄환 한 발을 발사한다.
- 사용자 답변에 따라 원형 보호막은 보호막을 통과하는 플레이어 발사체만 차단한다. 폭발·잔류·빔은 보호막 때문에 차단하지 않는다. 따라서 원문의 안쪽 진입은 발사체로 공격할 때의 해법이며, 모든 공격에 필수인 조건은 아니다.
- 보호막에 충돌한 발사체는 사라진다. 보호막 충돌의 `OnHit` 동작은 원문에서 후속 기획으로 남겼으므로 이번 구현에서는 발생시키지 않는다.
- 캐리어는 Prefab Inspector에서 생성 대상 목록, 생성 주기, 회당 생성 수를 설정한다. 사용자 답변에 따라 사망하면 이후 생성만 중단하며, 이미 생성한 적은 살아남는다.
- 인터셉터는 플레이어 주변을 1초 이동하고, 느린 탄환을 발사하면서 0.2초 정지한 뒤 같은 행동을 반복한다.

HP, 이동 속도, 피해, 반경, 보상, 등장 스테이지 등 원문에 없는 수치는 아래의 초기 제안값이다. 확정된 1초·0.1초·0.2초 동작 시간과 사용자 답변은 유지하고, 나머지는 실제 전투 검증 후 조정한다.

확인한 현재 구조의 주의점:

- Unity 버전은 `6000.3.22f1`이다. 적 행동과 충돌의 원본은 `RuneSimulation`이며, 월드 Prefab 자체에서 전투 AI를 실행하지 않는다.
- 플레이어 발사체에는 이동 경로 판정이 있지만, 적 탄환은 현재 이동 후 위치로 플레이어와의 겹침을 확인한다. 고속 저격탄에는 경로를 따라 충돌을 검사하는 확장이 필요하다.
- 현재 피해 함수에는 플레이어의 GPU 피해 배율과 적응 학습이 함께 들어간다. 적의 자폭 피해를 이 함수에 그대로 넘기면 플레이어 강화가 자폭 피해를 바꾸는 문제가 생긴다.
- 이지스는 전방 볼트 피해 감쇠이며 실제 발사체 차단이 아니다. 새 원형 보호막은 별도 특성으로 처리한다.
- 일반 스테이지는 기본 흐름에서 생성된 목표 적의 처치 수로 끝난다. 웨이브·분열 자식·보스 증원은 현재 목표 처치 수에 포함되지 않는다.
- `StageCatalog.Get`은 단일 스테이지 항목을 공통 범위보다 우선한다. 공통 후보만 편집해서는 1~5·10스테이지의 개별 편성이 모두 바뀌지 않는다.
- `MissionWorldAssets`는 기존 Prefab을 재생성하지 않는다. 생성기 수정과 기존 Prefab 연결을 함께 수행해야 한다.

### 4. 종류별 구현 계획과 완료 기준

#### 4.1 자폭 씨앗

역할: 가까이에서 처치하면 위험하고, 적 무리 안에서 처치하면 연쇄 피해를 활용할 수 있는 적.

- 스카우트의 추적·접촉 공격을 재사용하고 사망 폭발 특성을 추가한다.
- 사망 위치에서 즉시 한 번 원형 피해를 적용한다. 폭발 표시는 짧게 남기되 판정은 한 번만 한다.
- 플레이어는 기존 피격 무적·대시 무적·보호막 규칙에 따라 피해를 받는다. 적은 각 대상마다 한 번 피해를 받는다.
- 적의 자폭 피해 경로는 플레이어 GPU 배율, 플레이어 DPS 집계, 룬 적중 이벤트와 적응 학습을 적용하지 않는다. 보스 패치 무적과 릴레이의 주변 피해 감소는 보존하는 안으로 계획한다.
- 폭발 피해로 다른 씨앗이 죽으면 연쇄 폭발한다. 사망 처리를 큐로 진행해 목록을 순회하며 삭제하거나 깊은 재귀를 만들지 않고, 각 사망 적은 한 번만 정산한다.
- 연쇄 폭발로 처치된 기본 흐름의 목표 적은 기존 목표 처치 수에 포함한다. 분열형의 자식 생성과 기존 처치 보상도 정상 처리한다.
- 클리어·중단·씬 전환으로 제거하는 적은 사망 폭발을 발생시키지 않는다. 디버그 전체 처치는 실제 사망 효과와 구분해 플레이어를 죽이지 않는 정리 동작으로 유지한다.

완료 기준: 플레이어·적 범위 피해, 씨앗 연쇄 폭발, 대상당 단발 피해, 보상 중복 없음, 종료 시 폭발 없음, 플레이어 피해 강화와 자폭 피해의 독립성을 확인한다.

#### 4.2 초침 저격수

역할: 조준을 읽고 발사 직전에 횡이동하거나 대시하도록 유도하는 원거리 적.

- 기존 센트리 탄환을 재사용하되 저격 공격 방식을 추가한다. 60Hz에서 추적 60틱, 고정 6틱 후 발사한다.
- 조준 시작부터 발사까지 이동을 멈추고, 첫 1초 동안 조준선만 플레이어를 따라 돌린다.
- 추적 종료 시 발사 시작점과 방향을 고정한다. 적 분리로 몸체가 움직여도 탄환은 마지막 표시 경로를 따른다. 표시와 판정은 같은 시작점·방향·벽 제한 경로를 사용한다.
- 0.1초 고정 구간에서도 고정된 조준선을 표시한다. 레이저 자체는 피해를 주지 않는다.
- 사망하면 발사 예약을 취소한다. 빙결되면 조준을 취소하고 해제 후 1초 조준부터 다시 시작하는 안으로 계획한다.
- 적 탄환의 이동 전후 경로와 플레이어·벽 충돌을 검사해 한 틱에 대상을 통과해도 적중한다. 벽과 플레이어 중 먼저 닿는 것을 처리하고, 일반 센트리 탄환과 보스 장판 동작도 함께 확인한다.
- 발사 간격 3초는 초기 제안이다. 첫 발 이후 다음 조준 시작은 재발사까지의 추적·고정 시간을 제외한 대기 시간으로 계산한다.

완료 기준: 60틱 추적 → 6틱 고정 → 단발 발사, 붉은 반투명 점멸 예고, 고정 경로 유지, 고속 탄환의 관통 누락 없음, 벽 차단, 사망·빙결 시 발사 취소를 확인한다.

#### 4.3 원형 보호막 근접형·원거리형

역할: 발사체 공격에는 진입을 요구하고 폭발·잔류·빔으로는 대응할 수 있는 적. 두 종류는 보호막 판정을 공유한다.

- 근접형은 스카우트의 추적·접촉, 원거리형은 현재 센트리의 이동·예고·3연탄을 재사용한다.
- 보호막은 소유 적의 위치를 따라가는 원형 경계다. 플레이어와 적의 이동을 가로막지 않고, 적 탄환도 차단하지 않는다.
- 바깥에서 들어오는 플레이어 발사체는 몸체보다 먼저 보호막에 충돌해 소멸한다. 관통 수가 남아 있어도 통과하지 않는다.
- 보호막 안쪽에서 생성된 발사체는 내부의 적을 공격할 수 있다. 안쪽에서 바깥으로 나가는 발사체는 허용하는 안으로 계획한다.
- 구형·사각·부채꼴 발사체 각각의 실제 충돌 크기를 반영한다. 보호막과 몸체, 다른 적의 충돌 후보 중 경로상 가장 먼저 만난 것을 판정하며 동률 순서를 고정한다.
- 보호막에 막히면 적 피해·상태 이상·`OnHit`을 발생시키지 않는다. 자연 수명 종료가 아닌 충돌 소멸이므로 `OnExpire`·`OnFirstHitOrExpire`도 실행하지 않는 안으로 계획한다. 후속 보호막 이벤트는 이번에 추가하지 않는다.
- 폭발·잔류·빔·공전과 이미 부여된 상태 이상은 그대로 처리한다. 외부에서 내부에 생성한 범위 마법도 허용한다.
- 이지스의 EMP 무력화 규칙은 자동으로 상속하지 않는다. 원형 보호막의 체력·파괴·재생·EMP 무력화는 원문에 없으므로 이번 범위에 추가하지 않는다.

완료 기준: 근접·원거리 행동 보존, 외부 발사체 차단, 내부 발사체 적중, 관통 차단, 세 발사체 모양의 경계 판정, 폭발·잔류·빔 허용, 적 탄환·이동 허용, 보호막 충돌 이벤트 없음과 기존 이지스 보존을 확인한다.

#### 4.4 캐리어

역할: 생존할수록 주변 적을 늘려 우선 처치를 유도하는 생성형 적.

- 기존 적 Prefab의 Variant로 제작하고 생성 설정 컴포넌트를 연결한다. Inspector에는 생성할 적 Prefab 목록, 생성 주기, 회당 생성 수, 생성 거리, 이 캐리어가 생성한 생존 적의 최대 수를 둔다.
- 각 생성 대상 Prefab에는 카탈로그의 안정된 적 ID를 연결한다. 대상 Prefab의 몸체는 표시용이며 HP·공격 수치의 원본은 계속 `enemies.json`이다.
- 신규 적 Variant는 `Resources/RuneCode/Enemies/`에 두는 안으로 계획한다. 기본 캐리어 설정은 해당 Prefab에서 읽고, 생성 대상 기본값은 인터셉터로 연결한다.
- Unity 계층에서 Prefab 설정을 적 ID와 수치만 가진 읽기 전용 설정으로 변환해 시뮬레이션 생성 시 전달한다. 미션·도크·CLI가 같은 변환 경로를 사용하며 `RuneCode.Core`에서 UI 컴포넌트를 참조하지 않는다.
- 생성은 `RuneSimulation`의 틱에서 수행한다. Prefab의 `Update`나 Coroutine이 직접 적을 생성하지 않는다. 표시 뷰가 재사용되어도 생성 설정과 실행 상태는 영향을 받지 않는다.
- 목록은 Inspector 순서대로 순환하는 안으로 계획한다. 생성 시각, 목록의 다음 위치, 미완료 회차와 생성 소유자 ID는 캐리어별 실행 상태로 관리한다.
- 생성 위치는 캐리어 주변이며 부모·자식 몸체 크기와 벽을 고려한다. 전체 적 상한 또는 캐리어별 생존 상한에 걸리면 아직 생성하지 못한 수만 보류하고, 대기 회차를 무제한 누적하지 않는다.
- 사망하면 미완료 생성과 다음 생성 일정을 취소한다. 이미 생성된 적은 계속 행동하며, 전투 종료 시에는 다른 적과 함께 기존 종료 규칙을 따른다.
- 빙결 중에는 생성 타이머를 멈추는 안으로 계획한다. 생성 상한의 초기 제안은 캐리어당 생존 자식 6체다.
- 생성된 적은 기존 증원처럼 목표 처치 수에 포함하지 않는다. 반복 생성에 따른 재화 파밍을 막기 위해 생성 자식은 기본 스크랩·아이템 드롭을 0으로 하는 안으로 계획한다. 캐리어 본체에는 정상 보상을 지급한다.
- 생성 대상 목록은 일반 적으로 검증하고 보스, 자기 자신, 캐리어를 다시 생성하는 순환 설정은 거부하는 안으로 계획한다.

완료 기준: Inspector 대상·주기·회당 수 변경이 실제 생성에 반영되고, 미션·도크·CLI에서 같은 설정이 적용되며, 상한에서 미완료 수 보류, 사망 시 생성 취소, 기존 자식 생존, 종료 후 예약 없음, 자식의 목표 처치·보상 분리를 확인한다.

#### 4.5 인터셉터

역할: 플레이어 주변을 돌아 조준을 분산시키고 느린 탄환으로 공간을 압박하는 캐리어의 기본 생성 적.

- 플레이어와의 거리를 조절하면서 접선 방향으로 움직이는 이동 방식을 추가한다. 유지 거리 초기 제안은 180px이며, 회전 방향은 생성 순서로 번갈아 정해 재현 가능하게 한다.
- 60틱 이동한 뒤 플레이어 방향으로 탄환 한 발을 발사하고 12틱 정지한다. 이후 다음 60틱 이동으로 돌아간다.
- 사격 방향은 발사 시점에 정하고, 탄환은 센트리보다 느린 직선탄으로 처리한다. 접촉 피해는 초기 계획에서 넣지 않는다.
- 빙결 중에는 행동 주기 진행을 멈추고, 냉기는 이동 속도에 기존 감속을 적용하는 안으로 계획한다.
- 새로 생성된 적은 생성한 틱에 행동을 중복 실행하지 않고 다음 행동 갱신부터 시작한다.
- 캐리어가 죽어도 행동을 계속한다. 기본 편성은 캐리어 생성 전용이며 디버그에서는 단독 생성할 수 있게 한다.

완료 기준: 플레이어 주변 이동, 정확한 60틱 이동·12틱 정지 반복, 주기당 단발 사격, 느린 탄환, 냉기·빙결 반영, 캐리어 사망 후 독립 행동을 확인한다.

### 5. 외형과 Prefab 연결 계획

| 적 | 기존 도형을 사용하는 외형 제안 | 추가 표시 |
|---|---|---|
| 자폭 씨앗 | 주황색 원형, 어두운 중심부 | 사망 위치의 짧은 폭발 링·채움 |
| 초침 저격수 | 짙은 붉은 마름모 | 붉은 반투명 점멸 조준선, 가는 고속 탄환 잔상 |
| 보호막 근접형 | 청록색 삼각형 | 몸체보다 큰 청록색 원형 보호막 |
| 보호막 원거리형 | 청록색 마름모 | 몸체보다 큰 청록색 원형 보호막, 기존 사격 예고 |
| 캐리어 | 남색 팔각형, 어두운 중심부 | 생성 직전·직후의 짧은 링 변화 |
| 인터셉터 | 밝은 붉은 작은 삼각형 | 이동 방향 회전, 기존 적 탄환 표시 |

- 공통 `MissionEnemy.prefab`을 기반으로 6종 Variant를 만든다. 저격선·보호막 같은 종류별 표시만 필요한 자식으로 추가하며, 공통 체력·상태·엘리트 표시는 상속한다.
- 월드 뷰는 적 종류에 연결된 Prefab을 선택한다. 기존 목록 재사용 방식을 종류별로 확장해 다른 종류의 Variant를 그대로 재사용하지 않도록 한다.
- 몸체·색·예고·보호막·조준선은 매 적용 시 해당 적 상태로 갱신한다. 비활성화와 재도전 시 지난 적의 표시가 남지 않도록 한다.
- 보호막 표시 반경과 실제 충돌 반경, 저격선 방향과 실제 탄환 경로는 동일한 시뮬레이션 값을 읽는다. 저격선 점멸도 틱 기반 진행 상태를 사용해 일시정지 중 진행하지 않는다.
- 도크에는 신규 도형·색·보호막·저격선·폭발 잔상을 같은 의미로 반영한다. 월드와 도크의 픽셀→좌표 변환은 기존 방식을 유지한다.
- 기존 Prefab과 생성기의 연결을 Unity Editor/API로 갱신한다. 기존 Variant 상속과 `.meta` GUID를 보존한다.

### 6. 등장 편성과 보상 연결 제안

기존 스테이지의 클리어 조건·성장·엘리트 주기·보스 시간은 유지하고, 일반 스폰 후보에 낮은 비중으로 추가하는 안이다. 아래 등장 시점과 가중치는 제안이며 원문에 지정된 내용은 아니다.

| 적 | 최초 등장 제안 | 스폰 가중치 제안 | 의도 |
|---|---:|---:|---|
| 자폭 씨앗 | 2 | 1 | 사망 폭발과 적에게 주는 피해 학습 |
| 초침 저격수 | 3 | 0.4 | 조준 예고와 횡이동·대시 학습 |
| 보호막 근접형 | 4 | 0.5 | 내부 진입 또는 다른 공격 행동으로 대응 |
| 보호막 원거리형 | 6 | 0.4 | 원거리 압박 중 보호막에 대응 |
| 캐리어 | 7 | 0.25 | 생성 적 대응과 본체 우선 처치 |
| 인터셉터 | 캐리어 생성 | 해당 없음 | 캐리어 행동의 결과로 등장 |

- 2·3·4스테이지는 해당 단일 항목과 공통 범위 항목을 각각 수정한다. 6 이후는 현재 공통 범위 후보에 연결한다.
- 1스테이지와 5·10 보스 스테이지의 기존 편성은 이번 초기안에서 유지한다.
- 신규 일반 적 보상은 `stages.json`의 미션 보상표에 연결한다. 생성 자식의 보상 제외는 생성 출처 규칙으로 처리해 스카우트 등 다른 적을 캐리어 목록에 넣어도 일관되게 적용한다.
- 실제 편성 전에는 기존 디버그 팝업에서 6종을 직접 선택해 생성할 수 있도록 확장한다. 도크·Editor에서도 공개 시뮬레이션 API로 개별 동작을 확인할 수 있게 한다.

### 8. 검증할 상황

- 자폭 씨앗: 플레이어·일반 적·보스·분열형이 함께 있는 범위, 씨앗 여러 체의 연쇄 사망, 동시에 사망한 적의 단일 정산, 마지막 목표 처치와 플레이어 사망이 겹치는 상황.
- 초침 저격수: 플레이어 이동·대시, 조준 중 분리 이동, 빙결·사망, 벽 앞 사격, 고속 탄환의 한 틱 통과, 여러 저격수의 동시 예고.
- 보호막 두 종류: 외부·내부·경계에서 발사, 구형·사각·부채꼴·고속·관통 발사체, 여러 보호막 중 먼저 만나는 경계, 폭발·잔류·빔·공전·상태 이상, 적 탄환과 플레이어 진입.
- 캐리어·인터셉터: Inspector 대상 교체·목록 순환·주기·회당 수 변경, 여러 캐리어, 생성 상한, 벽 주변 생성, 빙결, 부모 사망, 생성 자식의 독립 행동·보상·목표 처치 제외.
- 공통: 일시정지·재개, 중단·사망·클리어·시간 초과·재도전, 기존 스카우트·센트리·헌터·이지스·릴레이·분열형·거버너, 실제 월드와 도크 표시.
- 새 일정·방향·대기 생성·소유자·행동 주기 상태는 기존 상태 해시에 기록한다. 같은 시드·입력으로 개별 및 혼합 상황을 반복해 재현성을 확인한다.

### 9. 계획 작성 당시 확인 결과

- 원본 아이디어의 6종을 확인했고, 기존 데이터·행동·피해·스폰·표시·Prefab 생성 경로를 코드로 검토했다.

### 10. 구현 결과와 설정

- P1~P4: 6종 데이터·행동, 공통 적 Prefab을 상속하는 6개 Variant, 월드·도크 표시, 디버그 소환 버튼, 일반 등장 후보·단계·처치 보상을 연결했다. 기존 Scene 배치는 변경하지 않았다.
- `Assets/RuneCode/Resources/RuneCode/enemies/Carrier.prefab`의 `CarrierSpawnSettings`에서 생성 대상 `EnemyView` Prefab 목록, 주기, 회당 수, 거리, 생존 상한을 편집한다. 기본 연결은 Interceptor, 4초, 2기, 120px, 최대 6기다. 목록은 순환하며 생성형·보스 대상은 검증에서 거부한다. 미션·도크·CLI가 이 Prefab 설정을 공통으로 읽는다.
- `Rune Code > Prepare Additional Enemies` 메뉴는 누락된 자산·참조를 보충한다. 이미 생성한 Variant와 Inspector 조정값은 유지한다. 현재 6개 Variant와 생성 대상 참조는 연결되어 있어 추가 Inspector 작업은 필요하지 않다.
- 자폭 피해는 적 자체의 피해 배율을 사용하며 플레이어 GPU 강화·DPS·적응 학습에는 포함하지 않는다. 연쇄 사망을 큐로 정산한다. 캐리어 자식은 목표 처치 수·스크랩·아이템 드롭에서 제외하며, 부모 사망 후 독립적으로 남는다.
- P5에서 실제 확인한 항목: Unity 6000.3.22f1 재컴파일 성공, 6개 Variant 상속·필수 참조·Missing Script 검사 통과, Play에서 신규 외형·보호막·저격선 표시 확인. 디버그 버튼 6개를 실행해 6기가 생성되었고, 팝업 재개방 후 한 번 클릭하면 1기만 추가되었다. 이 과정의 새 런타임 오류는 없었다.
- 메모리 시뮬레이션으로 구형·사각·부채꼴 발사체의 외부 차단·내부 적중, 폭발·잔류·빔·궤도 허용, 차단 시 `OnHit`·`OnExpire`·`OnFirstHitOrExpire` 미발생을 확인했다.
- 저격은 1초 추적과 0.1초 고정 대기를 거쳐 발사했고, 빙결 시 조준 취소·해제 후 재조준했다. 인터셉터는 60틱 이동 후 발사·정지하고 12틱 후 이동을 재개했다. 미션에서 6000px/s 탄환이 한 틱에 플레이어를 지나가는 상황도 적중했다.
- 캐리어는 240틱에 첫 2기를 생성하고 최대 6기에서 멈췄다. 부모 처치 후 기존 6기가 남고 추가 생성은 없었다. 별도 생성 설정으로 대상 순환, 회당 수보다 낮은 상한, 자식 사망 후 보류 생성 재개, 자식 보상 0을 확인했다.
- 연쇄 자폭으로 주변 적 3기 처치와 플레이어 20 피해를 확인했다. GPU 배율을 100으로 설정해도 폭발 피해와 DPS 집계는 변하지 않았다. 같은 시드·입력으로 신규 6종이 섞인 900틱을 두 번 진행했을 때 매 틱 상태 해시가 일치했다. 도크 초기화 시 남은 적 탄환은 제거되었다.
- 등장 검증에서 스테이지 2의 자폭 씨앗, 3의 초침 저격수, 4의 보호막 근접형, 6의 보호막 원거리형, 7의 캐리어·생성 인터셉터를 확인했다. 초기 설정의 저격수는 시드 1에서 2562틱에 처음 등장했다. 저격수·인터셉터의 음수 탄환 수명은 데이터 검증에서 거부되었다.
- Windows 빌드로 실행한 CLI와 Editor의 스테이지 7·10 결과는 실행 소요 시간을 제외한 모든 필드가 일치했다. 스테이지 7은 913틱·상태 해시 `b06fad3c`, 기존 보스 스테이지 10은 695틱·`6529df19`였으며 두 실행 모두 플레이어 사망으로 종료했다. 이는 보스 클리어 검증을 뜻하지 않는다.
- 최종 Windows 빌드: `Builds/RuneCodePoC-AdditionalEnemies/RuneCodePoC.exe`, 결과 `Succeeded`, 오류 0개·경고 1개. 경고는 기존 프로젝트의 `RuntimePipelineConfig` 미설정으로 Player에서 Unity Pipeline 도구 연결이 꺼진다는 내용이며 전투 구현 오류는 아니다. 초기 동기 빌드 호출의 도구 응답 시간 초과는 기본 비동기 빌드로 해소했다.
- 남은 확인: 장시간 플레이에 따른 초기 수치·등장 가중치 조정, 모든 기존 적·보스와의 전체 조합, 화면 크기별 가독성. 위 8절의 전체 상황을 모두 실행한 것은 아니다.
