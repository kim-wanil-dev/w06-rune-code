# Rune Code 구현 결정

- 2026-10-07: 기존 Unity 6000.3.22f1 프로젝트와 Input System 1.20.0을 재사용한다. PRD의 웹 스택은 미확정 엔진의 가정이므로 게임 규칙을 C#으로 구현하고 Windows x64 PoC를 배포한다.
- AGENTS.md를 우선하여 Git CLI, 커밋, push, 테스트 코드 및 테스트 자산 추가를 수행하지 않는다. 기존 AGENTS.md와 PRD는 변경하지 않는다.
- 수치 및 콘텐츠는 Resources/RuneCode JSON에서 읽는다. 게임 규칙은 Core에 두고 Game/UI는 입력, 표시, 저장 연결을 맡는다.
- 신규 전용 장면 RuneCodePoC를 Unity Editor API로 구성하여 기존 SampleScene과 기존 자산을 보존한다.
- 포트 입력·연결·장착 검증은 컴파일러와 편집기가 공유한다. 미해금 룬과 용량 초과 보관함 마법은 열람할 수 있으나 장착하지 못한다.
- 그래픽은 uGUI 메시로 생성한 도형을 사용한다. 한글 UI는 Windows 설치 글꼴을 TMP DynamicOS로 조회하며 외부 아트·오디오를 추가하지 않는다.
- 검증은 제작한 게임의 공개 API, Unity 컴파일 결과, 실제 Play 모드 화면, 빌드 리포트 및 실행 로그로 기록한다. 테스트 코드와 커버리지 수치는 생성하지 않는다.
- 지연 룬의 실행 출력 포트는 PRD의 비용·런타임·Action 스키마와 일치하는 `then`을 사용한다. 포트 표의 `next` 표현은 점멸·방벽에 적용하며 편집기와 JSON도 같은 포트 ID를 사용한다.

- 2026-10-07 인크리멘탈 전환: 사용자 변경 요청을 기존 PRD의 방·터미널·보스 진행 및 여러 마법 슬롯 규칙보다 우선한다. 제한시간 전투→처치 RAM 정산→동일 마법 노드 확장을 반복한다.
- 전투 조작에 대한 선택 응답이 없어 인크리멘탈 흐름에 맞춰 가장 가까운 적 자동 조준·시전을 기본으로 사용한다. 플레이어는 왼쪽에 시작하며 기존 점멸 룬 이동은 유지한다.
- 별도 성장은 용량+2, EN+10 및 초당 회복+1, 전투시간+5초로 한다. 시작 가격12/15/18, 배율1.22, 최대100/100/18단계는 기존 balance.json에서 관리한다.
- 일반 스테이지의 적응 감쇠는 incremental.json의 설정으로 비활성화한다. 도크 적응 검사와 기존 룬 효과는 재사용한다.
- v2 파일로 진행을 이전하며 기존 v1 파일을 수정하지 않는다. A 마법 하나를 활성으로 유지하고 다른 설계는 보존한다. C 구매 비용120을 환불하며 기존 체력 성장은 보존한다.
- 중첩 반복에 의한 무제한 예약을 방지한다. 컴파일 실행 수2048, 예약2048, 틱당 실행512, 생존 적300 상한을 기존 설정과 컴파일러·시뮬레이션에 추가한다.
- 기존 배포를 보존하기 위해 인크리멘탈 EXE와 ZIP은 RuneCodePoC-Incremental이라는 별도 경로로 생성한다.

- 2026-10-07 수동 조작·수식 커스텀: 사용자 요청에 따라 앞선 자동 이동·자동 조준 선택을 대체한다. WASD 이동과 마우스 조준, 기존 Space 대시·Esc 일시정지를 연결한다. 포인터가 전투 영역에 있을 때 하나의 마법을 연속 시전하는 방식은 유지한다.
- 사거리·속도 수식은 벤치에서 각각20 RAM으로 해금한다. 크기는 기존 확장 수식을 확장하여 조절하며 기존30 RAM 비용과 피해·에너지 배율을 보존한다. 세 배율의 범위0.5~3, 단계0.1, 기본1.5는 runes.json에서 관리한다. 형태당 속성·수식3개 제한을 유지한다.
- 속도 조절로 볼트 비행 거리가 함께 변하지 않도록 비행 시간을 반대로 조절한다. 사거리는 볼트 비행 거리·버스트/존 생성 거리·오비트 궤도 거리, 크기는 충돌 반경·오비트 궤도 크기, 속도는 볼트 이동·오비트 회전에 반영한다. 버스트/존의 속도 수식에는 효과 없음 경고W2를 표시한다.
- 개별 노드 배율을 기존 그래프 파라미터에 저장하여 저장·RC1 공유·Undo/Redo 구조를 재사용한다. 이전 확장 노드에 배율이 없으면 기존1.5배를 사용한다. CLI incremental은 비교용 자동 조준 입력으로 유지하며 실제 플레이 조작과 구분하여 안내한다.
- 수동 조작·커스텀 빌드는 RuneCodePoC-ManualMods 경로로 출력하여 이전 배포와 사용자 저장을 보존한다.

- 2026-10-08 onComplete 의미 변경: 형태·마법 호출의 `onComplete` 포트를 `onFirstHitOrExpire`로 바꾸고, 시전 직후 즉시 실행 대신 개체마다 첫 적중 또는 소멸 중 먼저 일어난 이벤트에서 한 번만 실행한다. 적중이면 피격 대상, 소멸이면 대상 없음 컨텍스트를 쓴다. 마법 호출은 호출한 마법이 만든 개체마다 같은 규칙을 적용한다. 버프는 적중·소멸 이벤트가 없어 같은 포트를 적용 직후 실행으로 유지한다. 모델 응답 23개 A/B 설문에서 선호 동작(②61%)과 이름(onFirstHitOrExpire 52%)을 근거로 했다. 기존 저장·공유 코드의 onComplete 연결은 SpellGraphMigration에서 새 포트로 이전한다. 컴파일러 비용·개체 수·실행 수는 개체당 한 번으로 계산한다.

- 2026-10-08 구조 분리·테이블화: 문법 엔진(`Core/Graph`, `RuneCode.Grammar`)과 테이블 기반(`RuneCode.Tables`)은 UnityEngine을 참조하지 않는 순수 C# 어셈블리로 둔다. 저장·공유 JSON은 Unity 계층의 `SpellGraphData`가 기존 키 그대로 담당한다. 게임 데이터는 정규화 CSV로 옮기며 이번에는 룬 테이블 6종만 전환했다. 규칙은 `docs/DATA_TABLES.md`. 노드별 쿨다운 기여값과 Interpreter 분리는 별도 작업으로 미룬다.
