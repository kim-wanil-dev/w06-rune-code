# 마법 그래프 구현 규칙 (최종안)

> 「마법 그래프 규칙 v1」(개정 r3)을 프로토타입 구현용으로 다시 쓴 문서다. 설계 근거와 변경 이력은 그 문서에 있다.
> 이 문서는 기존 시스템을 리팩토링할 때 **규칙의 단일 기준**이다. 기존 구현과 다르면 이 문서를 따른다.
> 이름, 폴더 구조, 입력 체계, UI 문구 언어, 전투 진행(전투 중 여부 판정 포함)은 기존 시스템을 따른다. 괄호 안의 영문 이름은 참고용이다.

**읽는 법**
- 숫자는 전부 11절 설정값에 모은다. 본문 숫자는 기본값이다.
- 7.3의 「바꾸면 안 되는 규칙」은 리팩토링 중에도 유지한다. 지우면 무한 루프나 마나 복제가 생긴다.
- 12절의 검증 시나리오가 그대로 나오면 구현이 맞은 것이다.

---

## 1. 개요

- 플레이어는 노드를 흐름선으로 이어 마법 그래프 하나를 만든다. 편집은 전투가 아닐 때만 한다.
- 시전하면 그래프 위에 **토큰**이 생겨 흐름선을 따라 실시간으로 노드를 지나간다.
- 토큰은 마나를 싣고 출발하고, **노드에 도착할 때마다 비용을 지불**한다. 비용은 토큰이 들고 온 값에 따라 그때그때 계산된다.
- 비용을 낼 수 없으면 토큰은 그 노드 앞에서 소멸한다. 그 뒤의 노드는 실행되지 않는다.
- 투사체가 적에게 맞으면 그래프의 적중 노드에서 새 토큰이 태어나 실행을 이어 간다.
- 그래프는 하나이고 읽기 전용이다. 늘어나는 것은 토큰이다. **토큰마다 그래프를 복제하지 않는다.**

## 2. 데이터 구조

### 2.1 그래프 (SpellGraph)
- 플레이어당 1개다 (마법 슬롯 1개).
- 노드 : id, 종류, 파라미터, 편집기 좌표. **좌표는 표시용이며 규칙에 쓰지 않는다.**
- 포트 : 흐름 입력과 흐름 출력만 있다. 데이터 포트는 없다. 포트 수는 노드 종류가 정한다 (5절).
- 엣지 : (출발 노드, 출력 포트 번호) → (도착 노드, 입력 포트 번호). 엣지에는 비용도 시간도 없다.
- 출력 포트 하나에는 엣지가 최대 1개다. 입력 포트 하나에는 엣지가 여러 개 들어올 수 있다.
- 역방향 연결과 자기 자신으로의 연결을 허용한다. 이것이 루프다.

### 2.2 토큰 (Token)

| 필드 | 타입 | 시전으로 생길 때 | 설명 |
|---|---|---|---|
| 현재 노드 | 노드 id | 시전 노드 | |
| 다음 출력 포트 | int | 0 | 도착 처리에서 정한다. 분기·분배만 1을 쓴다 |
| 남은 대기 시간 | float | 시전 노드의 머무는 시간 | 0 이하가 되면 다음 노드로 간다 |
| 마나 | float | 적재량 | |
| 위력 | float | 10 | 비용 계산과 피해의 기준값 |
| 개수 | int | 1 | 투사체 노드가 한 번에 쏘는 수 |
| 원점 | 캐릭터 또는 지점 | 캐릭터 | 발사 위치. 지점이면 좌표를 함께 저장한다 |
| 방향 | 단위 벡터 (지면 평면) | 쓰지 않음 | 원점이 지점일 때만 쓴다. 원점이 캐릭터이면 발사할 때마다 계산한다 (6.1) |
| 세대 | int | 0 | 적중으로 태어날 때마다 1씩 늘어난다 |
| 통과 횟수 | 노드 id → int | 비어 있음 | 노드마다 도착해서 비용을 지불한 횟수 |
| 경과 시간 | float | 0 | 수명 판정용 |
| 무시할 적 | 적 참조 또는 없음 | 없음 | 이 토큰이 쏜 투사체는 이 적과 충돌하지 않는다 |
| 합류 대기 | 대기 포트, 대기 시간 | 없음 | 합류 노드에서 짝을 기다리는 중일 때만 쓴다 |
| 시전 id | int | 시전마다 새 번호 | 테스트·디버그용. 파생된 토큰과 투사체가 물려받는다 |

- 토큰의 값은 소멸할 때까지 초기화되지 않는다. 투사체를 쏴도 위력과 개수는 그대로다.

### 2.3 투사체 (SpellProjectile)
- 위력, 운반 마나, 세대, 무시할 적, 시전 id : 쏜 토큰에서 받는다. 운반 마나는 6.1에 따른다.
- 위치, 방향, 이동한 거리

### 2.4 마나풀
- 최대 100, 초당 8 회복. 값은 float다.
- 마나가 생기는 곳은 마나풀뿐이고, 마나풀에서 토큰으로 마나가 넘어가는 곳은 시전뿐이다.

## 3. 그래프 유효성

- 시전 노드는 항상 정확히 1개다. 삭제할 수 없다.
- 적중 노드는 0개 또는 1개다. 하나가 있으면 더 추가할 수 없다.
- 시전 노드와 적중 노드에는 입력 포트가 없다.
- **도달 가능한 노드** : 시전 노드나 적중 노드에서 흐름선을 따라 갈 수 있는 노드. 도달할 수 없는 노드는 편집기에서 회색으로 표시한다. 그런 노드는 실행될 일이 없으므로 따로 막지 않는다.
- 시전 노드에서 도달할 수 있는 투사체 노드가 없으면 경고를 표시한다. 시전은 막지 않는다.
- 노드 개수에는 제한이 없다.

## 4. 실행 규칙

### 4.1 시전
- 시전 입력을 한 번 누르면 시전을 한 번 시도한다. 누르고 있어도 반복하지 않는다.
- 편집 모드 중에는 무시한다.
- 실패 조건 (마나를 차감하지 않고, 토큰도 만들지 않는다)
	- 마나풀 < 적재량 → '마나 부족' 표시
	- 활성 토큰 수가 상한(64)에 도달 → '과부하' 표시
- 성공하면 마나풀에서 적재량을 빼고, 2.2의 초기값으로 토큰을 하나 만든다.
- 시전 노드는 토큰에게 비용을 받지 않는다.

### 4.2 프레임 처리 순서
1. 마나풀 회복
2. 투사체 이동과 충돌 처리 (6.2). 적중으로 생긴 토큰은 토큰 목록에 추가만 한다. **이 토큰들은 다음 프레임부터 처리한다.**
3. 토큰 처리 (4.3). 생성 순서대로 한다. 투사체 노드는 투사체를 바로 만들지 않고 **발사 요청**을 모은다.
4. 모은 발사 요청을 묶어 투사체를 만든다 (6.1). 새 투사체는 다음 프레임부터 움직인다.

### 4.3 토큰 처리 (토큰 하나, 프레임 하나)
```
경과 시간 += dt
경과 시간 > 수명(3초) 이면 → 소멸(수명 초과), 끝

합류 대기 중이면
    대기 시간 += dt
    대기 시간 < 합류 최대 대기(1.0초) 이면 → 끝
    대기 해제, 남은 대기 시간 = 0, 다음 출력 포트 = 0  (짝 없이 혼자 진행)

남은 대기 시간 -= dt
[진행 루프] 최대 32회 반복:
    남은 대기 시간 > 0 이면 → 끝
    엣지 = 현재 노드의 [다음 출력 포트]에 연결된 엣지
    엣지가 없으면 → 정상 종료, 끝
    현재 노드 = 엣지의 도착 노드
    결과 = 도착 처리(토큰, 도착 노드, 엣지의 입력 포트 번호)    ← 4.4
    결과가 '소멸', '종료', '대기', '합쳐짐' 중 하나이면 → 끝
    남은 대기 시간 += 도착 노드의 머무는 시간
```
- 남는 시간을 다음 노드로 넘기므로, 프레임 속도가 달라도 같은 그래프는 같은 박자로 실행된다.
- 머무는 시간은 적중 노드 말고는 0보다 커야 한다 (최소 0.01초). 0이면 자기 자신으로의 루프에서 프레임이 멈춘다.
- **분배로 이번 프레임에 생긴 복제 토큰**은 같은 프레임 안에서 처리한다. 원본 토큰의 처리가 끝난 직후에 처리하며, 경과 시간과 대기 시간에 이번 프레임의 dt는 이미 반영되어 있으므로 **[진행 루프]부터 시작**한다. 이렇게 해야 두 갈래가 같은 프레임에 발사해서 6.1의 동시 발사로 묶인다.

### 4.4 도착 처리 (모든 노드 공통)
1. 비용을 계산한다 (5절 공식, **도착한 순간의 토큰 값**으로).
2. `토큰 마나 < 비용` 이면 → **소멸(지불 불가)**. 필요한 비용과 가진 마나를 기록한다. 끝.
	- 마나와 비용이 같으면 지불하고 마나 0으로 계속 간다.
3. 토큰 마나 −= 비용
4. 통과 횟수[이 노드] += 1
5. 노드 효과를 적용한다 (5절).

### 4.5 토큰이 끝나는 경우

| 종류 | 원인 | 마나 | 표시 |
|---|---|---|---|
| 소멸(지불 불가) | 비용 > 마나 | 사라짐 | 해당 노드 붉게 깜빡임 + "필요 X / 보유 Y" |
| 소멸(수명 초과) | 경과 시간 > 수명 | 사라짐 | 해당 노드 회색 깜빡임 |
| 정상 종료 | 연결되지 않은 출력 포트로 나감 | 사라짐 | 없음 |
| 종착 발현 | 출력 연결이 없는 투사체 노드에서 발사 | 투사체로 넘어감 | 없음 |
| 합쳐짐 | 합류 노드에서 다른 토큰에 흡수됨 | 흡수한 토큰으로 넘어감 | 없음 |

## 5. 노드 명세

### 5.1 요약

| 노드 | 입력 / 출력 포트 | 파라미터 | 비용 | 머무는 시간 |
|---|---|---|---|---|
| 시전 (Cast) | 0 / 1 | 조준 모드, 적재량 | 토큰에게는 0 (마나풀에서 적재량을 뺀다) | 0.05 |
| 투사체 (Projectile) | 1 / 1 | 없음 | `2 × 개수` | 0.25 |
| 증폭 (Amplify) | 1 / 1 | 배율 (1.1 ~ 3.0, 기본 2.0) | `max(1, 위력 × (배율 − 1) × 0.4)` | 0.05 |
| 가산 (Add) | 1 / 1 | 없음 | `3` | 0.05 |
| 분열 (Split) | 1 / 1 | 없음 | `max(1, 위력 × 0.15)` | 0.05 |
| 분배 (Fork) | 1 / 2 | 비율 (10 ~ 90%, 기본 50%) | `2` | 0.05 |
| 합류 (Join) | 2 / 1 | 없음 | `2` (도착하는 토큰마다) | 0.05 (합쳐진 뒤) |
| 분기 (Branch) | 1 / 2 | 조건, 비교(≥ / ≤), 기준값 | `1` | 0.05 |
| 적중 (OnHit) | 0 / 1 | 없음 | 0 | 0 |

- **비용 바닥값** : 시전·적중을 뺀 모든 노드의 비용은 최소 1이다. 위 공식에 이미 반영되어 있다.

### 5.2 노드별 효과

**시전**
- 토큰을 만든다 (4.1). 적재량 범위는 10 ~ 100, 기본 40.
- 조준 모드는 `커서 방향`, `가장 가까운 적` 두 가지다 (6.1).

**투사체**
- 발사 요청을 하나 만든다 (6.1). 요청 하나는 `개수`만큼의 발을 담는다.
- 출력 포트에 엣지가 없으면 **종착 발현**이다. 토큰은 요청을 만든 직후 끝나고 머무는 시간은 적용하지 않는다.

**증폭** : 위력 ×= 배율

**가산** : 위력 += 10

**분열** : 개수 += 1, 위력 ×= 0.7

**분배**
- 비용을 낸 뒤 남은 마나를 `비율 : (1 − 비율)`로 나눈다.
- 원래 토큰은 앞쪽 몫을 갖고 출력 포트 0으로 간다.
- 복제 토큰은 뒤쪽 몫을 갖고 출력 포트 1로 간다. 마나를 뺀 모든 필드(경과 시간, 통과 횟수 포함)를 복사하고, 남은 대기 시간은 원본과 같게(머무는 시간을 더한 뒤의 값) 맞춘다. 처리 시점은 4.3을 따른다.
- 토큰 상한에 걸려 복제 토큰을 만들 수 없으면 뒤쪽 몫의 마나는 사라진다.
- 연결되지 않은 포트로 가는 토큰은 정상 종료한다.

**합류**
- 도착한 토큰은 먼저 비용을 낸다. 낼 수 없으면 그 자리에서 소멸한다.
- **반대쪽 포트에 기다리는 토큰이 있으면** 그중 가장 먼저 온 토큰이 지금 도착한 토큰을 흡수한다.
	- 흡수한 토큰 : 마나, 위력, 개수를 더한다. 나머지 필드는 흡수한 토큰의 값을 유지한다. 대기를 풀고, 남은 대기 시간 = 0.05, 다음 출력 포트 = 0
	- 흡수된 토큰 : '합쳐짐'으로 끝난다.
- **기다리는 토큰이 없으면** 도착한 포트에서 대기를 시작한다. 같은 포트에 여러 토큰이 기다리면 도착 순서대로 줄을 선다.
- 1.0초 동안 짝이 오지 않으면 혼자 출력 포트로 나간다. 추가 비용은 없다 (4.3).
- 기다리는 동안에도 경과 시간은 흐른다.

**분기**
- 비용을 낸 뒤 조건을 평가한다. 참이면 출력 포트 0, 거짓이면 출력 포트 1로 간다.
- 조건은 **토큰이 이 노드에 도착한 순간**의 값을 읽는다.

| 조건 | 읽는 값 |
|---|---|
| 대상 거리 | 토큰 원점에서 가장 가까운 적까지의 거리. 적이 없으면 조건은 거짓이다 |
| 대상 체력 % | 위와 같은 적의 `현재 체력 ÷ 최대 체력 × 100`. 적이 없으면 거짓이다 |
| 마나 | 토큰 마나. 분기 비용을 낸 뒤의 값이다 |
| 위력 | 토큰 위력 |
| 세대 | 토큰 세대 |
| 통과 횟수 | 통과 횟수[이 분기 노드]. 이번 도착을 포함한다 |

- 토큰 원점이 '캐릭터'이면 캐릭터의 현재 위치를 쓴다.
- 통과 횟수로 "이 분기를 3번째 지날 때 탈출" 같은 반복 횟수 루프를 만든다.

**적중**
- 플레이어가 직접 실행하지 않는다. 투사체가 적에게 맞았을 때 토큰이 생기는 자리다 (6.3).
- 생긴 토큰은 남은 대기 시간 0으로 시작해서 다음 처리 때 곧바로 출력 포트로 나간다.

## 6. 투사체와 적중

### 6.1 발사

투사체 노드는 아래 값을 담은 **발사 요청**을 만든다. 투사체는 그 프레임의 토큰 처리가 모두 끝난 뒤 한꺼번에 만든다 (4.2).

**발사 위치**
- 원점이 캐릭터이면 **발사 순간의 캐릭터 현재 위치**
- 원점이 지점이면 그 좌표

**기준 방향**
- 원점이 캐릭터이면 발사 순간에 시전 노드의 조준 모드를 적용한다.
	- 커서 방향 : 발사 위치에서 커서의 지면 좌표로 향하는 방향
	- 가장 가까운 적 : 발사 위치에서 가장 가까운 적으로 향하는 방향. 적이 없으면 커서 방향으로 대체한다
- 원점이 지점이면 (적중으로 태어난 토큰) 토큰의 방향 필드, 즉 **맞은 투사체의 진행 방향**을 그대로 쓴다. 조준 모드를 다시 적용하지 않는다.

**운반 마나** (마나 보존, 7절)
- 종착 발현이면 각 발이 `토큰의 남은 마나 ÷ 개수`를 운반한다. 토큰 마나는 0이 되고 토큰은 끝난다.
- 그 밖에는 운반 마나가 0이고, 토큰은 마나를 가진 채 계속 간다.

**그 밖의 값** : 위력, 세대, 무시할 적, 시전 id는 토큰 값을 그대로 넣는다.

#### 동시 발사 묶음과 부채꼴
같은 순간 같은 자리에서 같은 방향으로 여러 발이 나가면 겹쳐서 한 발처럼 보인다. 그래서 동시에 나가는 발들은 **각도를 나눠 부채꼴로** 쏜다. 원점이 캐릭터이든 지점이든 똑같이 적용한다.

1. 이번 프레임의 발사 요청을 생성 순서대로 하나씩 묶음에 넣는다.
	- 발사 위치가 같고(거리 0.1 이내) 기준 방향이 같은(각도 차 1° 이내) 묶음이 있으면 거기에 넣는다.
	- 단, 그 묶음에 **같은 토큰의 요청이 이미 있으면 넣지 않는다.** 한 토큰이 쏘는 요청들은 연사이므로 묶지 않는다.
	- 맞는 묶음이 없으면 새 묶음을 만든다.
2. 묶음의 총 발 수 M = 묶음 안 요청들의 `개수` 합
3. M발을 묶음 첫 요청의 기준 방향을 중심으로 부채꼴로 펼친다.
	- 인접한 발 사이 각도는 10°다. 전체 퍼짐 `(M − 1) × 10°`가 90°를 넘으면 90°를 M발로 균등하게 나눈다.
	- M = 1이면 기준 방향 그대로 쏜다.
4. 부채꼴의 자리는 요청 순서대로 차례로 배정한다. 각 발은 자기 요청의 위력, 운반 마나, 세대, 무시할 적을 그대로 갖는다.
5. 투사체 상한(200)을 넘는 발은 만들지 않는다. 비용은 이미 냈고, 만들지 못한 발의 몫 마나는 사라진다.

| 상황 | 결과 |
|---|---|
| 투사체 노드 3개를 연속으로 둔다 (개수 1) | 0.25초 간격으로 기준 방향을 향해 1발씩 나간다. 발사 시점이 다르므로 묶이지 않는다 (3연사) |
| 개수 3인 토큰이 투사체 노드 하나를 지난다 | 한 번에 3발이 −10°, 0°, +10°로 나간다 |
| 분배 뒤 두 갈래가 동시에 투사체 노드에 도착한다 (각 개수 1) | 같은 프레임, 같은 위치, 같은 방향이므로 한 묶음이 되어 −5°, +5°로 나간다 |
| 분배 뒤 두 갈래의 개수가 2와 1이다 | 3발 묶음이 되어 −10°, 0°, +10°로 나간다. 앞의 두 자리가 개수 2인 갈래의 발이다 |

### 6.2 비행과 충돌
- 직선 등속으로 날아간다. 속도 12, 최대 사거리 15 (기존 시스템 단위, 임시값).
- 충돌 대상은 적뿐이다. **무시할 적**과 플레이어는 통과한다.
- 벽이나 장애물에 닿거나 최대 사거리를 넘으면 소멸한다 (빗나감). **운반 마나는 사라진다.**
- 적에게 맞으면 아래 순서로 처리하고 투사체를 소멸시킨다. **관통하지 않는다.** 투사체 하나는 최대 한 번 맞는다.
	1. 피해를 준다 (8절).
	2. 운반 마나 > 0이고 그래프에 적중 노드가 있으면 적중 토큰을 만든다 (6.3).
- 한 프레임에 여러 적과 겹치면 이동 경로에서 가장 먼저 닿은 적 하나만 맞는다.

### 6.3 적중 토큰

| 필드 | 값 |
|---|---|
| 현재 노드 | 적중 노드 |
| 다음 출력 포트 / 남은 대기 시간 | 0 / 0 |
| 마나 | 투사체의 운반 마나 |
| 위력 | 투사체의 위력 |
| 개수 | **1** (상속하지 않는다) |
| 원점 | 지점 : 적중 위치 |
| 방향 | 맞은 투사체의 진행 방향 |
| 세대 | 투사체의 세대 + 1 |
| 통과 횟수 | 비어 있음 |
| 경과 시간 | 0 |
| 무시할 적 | 맞은 적 |
| 시전 id | 투사체의 시전 id |

- 맞은 적이 이 피해로 죽어도 토큰은 만든다.
- 이 토큰이 쏘는 투사체는 맞은 적을 지나 같은 방향으로 계속 나아간다. 개수가 늘었으면 그 방향을 중심으로 부채꼴로 갈라진다.
- 토큰 상한에 걸리면 만들지 않는다. 운반 마나는 사라지고 '과부하'를 표시한다.

## 7. 마나 보존과 상한

### 7.1 마나 보존
- 토큰과 투사체 사이에서 마나는 지불되거나, 나뉘거나, 합쳐지거나, 사라질 뿐 **늘어나지 않는다.**
- 마나가 옮겨 가는 경로는 분배(나눔), 합류(더함), 종착 발현(투사체에 나눔), 적중(투사체에서 토큰으로)뿐이다.
- 그래서 시전 1회의 총량은 그래프 모양과 관계없이 정해져 있다.
	- 시전 1회에서 나오는 투사체 수 합계 ≤ `적재량 ÷ 2` (투사체 1발마다 2를 내므로)
	- 시전 1회에서 지불이 일어나는 횟수 합계 ≤ `적재량 ÷ 1` (바닥값 1)

### 7.2 성능 상한 (설계 상한이 아니다)
- 활성 토큰 64, 활성 투사체 200
- 상한에 걸리면 새 토큰이나 투사체를 만들지 않고 '과부하'를 표시한다. 이때 만들지 못한 몫의 마나는 사라진다.
- 토큰 수명 3초, 토큰 하나가 한 프레임에 처리하는 노드는 최대 32개

### 7.3 바꾸면 안 되는 규칙
리팩토링 중에도 아래 규칙은 유지한다.

| 규칙 | 없애면 생기는 일 |
|---|---|
| 비용 바닥값 1 | 분열은 위력을 줄여 자기 비용도 줄인다. 비용 합이 유한한 값에 수렴해 무한 루프가 된다 |
| 종착 발현에서만 마나가 투사체로 넘어감 | 토큰과 투사체가 같은 마나를 동시에 가져 마나가 복제된다 |
| 적중 노드는 그래프당 최대 1개 | 한 번 맞을 때 토큰이 둘 이상 생겨 마나가 복제된다 |
| 투사체는 관통하지 않음 | 투사체 하나가 토큰을 여러 개 만든다 |
| 적중 토큰의 개수는 1 | 세대마다 투사체 수가 곱으로 늘어난다 |
| 적중 토큰은 맞은 적을 무시함 | 거리 0에서 같은 적을 바로 다시 맞혀 한 프레임에 연쇄가 폭주한다 |
| 분배 복제 토큰을 같은 프레임에 처리함 | 두 갈래의 발사가 한 프레임 어긋나 동시 발사 묶음이 깨지고 투사체가 겹친다 |
| 편집 모드에 들어가면 실행 중인 것을 모두 지움 | 그래프가 바뀐 뒤 남은 토큰이 사라진 노드를 가리킨다 |

## 8. 적 (이 시스템이 요구하는 값)

- 최대 체력, 현재 체력, 경감, 위치, 충돌체
- 피해 : `실피해 = max(0, 위력 − 경감)`. 체력이 0 이하가 되면 죽는다. 죽은 뒤의 처리는 기존 시스템을 따른다.
- 적 수치 (적 데이터에 둔다)

| 종류 | 경감 | 체력 |
|---|---|---|
| 더미 | 0 | 무한 (죽지 않는다) |
| 잡몹 | 12 | 60 |
| 방어형 | 40 | 200 |

- 잡몹의 경감이 기본 위력(10)보다 높은 것은 의도한 값이다. 키우지 않은 기본 투사체는 잡몹에게 피해를 주지 못한다. 경감 0인 적만으로 테스트하지 않는다.
- 적의 이동, 공격, 생성, 웨이브 구성은 이 문서의 범위가 아니다.

## 9. 편집 모드

- **편집은 전투가 아닐 때만 할 수 있다.** 전투 중에는 편집 모드에 들어갈 수 없다. 전투 중 여부와 편집 모드에 들어가는 방법은 기존 시스템을 따른다.
- **편집 모드에 들어가는 순간 남아 있는 토큰, 투사체, 합류 대기를 모두 지운다.** 마나는 돌려주지 않는다.
- 편집 모드 중에는 시전 입력을 무시한다.
- 편집 기능
	- 노드 추가 (팔레트), 이동, 삭제. 노드를 지우면 그 노드에 붙은 엣지도 지운다.
	- 엣지 연결 : 출력 포트에서 입력 포트로 끌어 놓는다. 이미 엣지가 있는 출력 포트에 연결하면 기존 엣지를 교체한다.
	- 엣지 삭제
	- 파라미터 수정 : 시전(조준 모드, 적재량), 증폭(배율), 분배(비율), 분기(조건, 비교, 기준값)
- 노드마다 비용 공식을 글자로 보여 준다 (예 : `위력×(2.0−1)×0.4`).
- 3절의 회색 표시와 경고를 보여 준다.

## 10. 표시 (프로토타입 최소)

- 마나풀 게이지
- 시전 실패 : '마나 부족', '과부하'
- **그래프 오버레이** : 플레이 중에 토글 키로 켜고 끈다. 그래프를 화면 일부에 작게 그린다.
	- 노드마다 지금 그 노드에 있는 토큰 수. 1개이면 점, 2개 이상이면 `×N` 배지
	- 노드마다 마지막으로 지불된 비용 (토큰이 지나갈 때마다 바뀐다)
	- 소멸 표시 : 4.5의 표대로 약 1초 동안 보여 준다
- 숫자는 소수 첫째 자리까지 표시한다. 내부 계산은 반올림하지 않는다.

## 12. 검증 시나리오

구현한 뒤 아래 결과가 그대로 나와야 한다. 마나와 위력은 내부값 기준이다.

**V1. 최소 마법** : `시전(적재 40) → 투사체`
- 마나풀 −40. 위력 10짜리 투사체 1발. 종착 발현이므로 운반 마나 38

**V2. 순서에 따라 결과가 달라짐** (적재 40)
- `시전 → 가산 → 증폭(×2) → 투사체` : 비용 3, 8, 2 → 위력 40, 남은 마나 27
- `시전 → 증폭(×2) → 가산 → 투사체` : 비용 4, 3, 2 → 위력 30, 남은 마나 31

**V3. 루프 도중 지불 불가** : `시전(60) → 가산 → 증폭(×2) → 분기(위력 ≥ 150)`, 참 → 투사체, 거짓 → 가산
- 1바퀴 : 가산(3) → 57, 위력 20 / 증폭(8) → 49, 위력 40 / 분기(1) → 48, 거짓
- 2바퀴 : 가산(3) → 45, 위력 50 / 증폭(20) → 25, 위력 100 / 분기(1) → 24, 거짓
- 3바퀴 : 가산(3) → 21, 위력 110 / 증폭 필요 44 > 보유 21 → **증폭 노드에서 소멸**. 발사 0발

**V4. 루프 탈출** : V3에서 기준값만 100으로 바꾼다
- 2바퀴째 분기에서 참 → 투사체(2) → 위력 100짜리 1발, 운반 마나 22

**V5. 분열 연쇄가 저절로 끝남** : `시전(60) → 투사체`, `적중 → 분열 → 투사체`
- 가정 : 적이 충분히 많아 모든 투사체가 맞는다. 피해는 이 검증과 관계없다.

| 세대 | 토큰 수 | 토큰당 마나 | 분열 뒤 위력 | 이 세대의 발사 수 | 1발당 운반 마나 |
|---|---|---|---|---|---|
| 0 | 1 | 60 | 10 (분열 없음) | 1 | 58 |
| 1 | 1 | 58 | 7 | 2 | 26.25 |
| 2 | 2 | 26.25 | 4.9 | 4 | 10.6 |
| 3 | 4 | 10.6 | 3.43 | 8 | 2.8 |
| 4 | 8 | 2.8 | 2.4 | 0 (투사체 노드 필요 4 > 보유 1.8 → 8개 모두 소멸) | — |

- 총 15발. 7.1의 상한 30발 안에 든다.
- 1세대 이후의 2발은 맞은 투사체의 진행 방향을 중심으로 −5°, +5°로 갈라진다.

**V6. 분배와 동시 발사** : `시전(40) → 분배(50%)`, 포트 0 → 투사체, 포트 1 → 투사체
- 분배(2) → 38 → 19 / 19. 각 투사체(2) → 운반 마나 17씩
- 두 갈래가 **같은 프레임에** 발사하고, 한 묶음이 되어 −5°, +5°로 나간다. 두 발이 겹쳐 한 발처럼 보이면 4.3의 복제 토큰 처리 시점이 틀린 것이다.

**V7. 합류** : `시전(40) → 분배(50%)`, 포트 0 → 가산 → 합류 포트 0, 포트 1 → 합류 포트 1, 합류 → 투사체
- 포트 1 쪽 토큰이 먼저 도착 : 합류(2) → 17, 대기
- 포트 0 쪽 토큰 : 가산(3) → 16, 위력 20 / 합류(2) → 14 → 흡수됨
- 합쳐진 토큰 : 마나 31, 위력 30, 개수 2 → 투사체(4) → 위력 30짜리 2발이 −5°, +5°로 나간다. 1발당 운반 마나 13.5

**V8. 바닥값이 무한 루프를 막음** : `시전(40) → 분열`, 분열의 출력을 자기 자신에게 연결
- 비용 1.5 → 1.05 → 그 뒤로 계속 1
- 39번 지불한 뒤 40번째 도착에서 필요 1 > 보유 0.45 → **지불 불가로 소멸**. 경과 시간 약 2.0초
- 수명 초과로 끝나면 바닥값이 빠진 것이다.

**V9. 연사는 묶이지 않음** : `시전(40) → 투사체 → 투사체 → 투사체`
- 0.25초 간격으로 1발씩 3발이 기준 방향으로 나간다. 캐릭터가 움직이거나 커서가 움직이면 2·3발째는 그 순간의 위치와 방향으로 나간다.
- 비용 2, 2, 2. 마지막 투사체 노드만 종착 발현이므로 3번째 발만 운반 마나 34를 갖고, 1·2번째 발은 0이다.

**V10. 편집 모드 진입** : 전투가 끝난 직후 토큰이나 투사체가 남아 있을 때 편집 모드에 들어가면 모두 사라진다. 전투 중에는 편집 모드에 들어갈 수 없다.

## 13. 범위 밖

이 프로토타입에서는 구현하지 않는다.
- 센서 노드와 데이터선 (분기 노드의 조건 목록이 그 역할을 대신한다)
- 원점이나 방향만 바꾸는 노드 (이동 노드, 조준 노드)
- 조준 모드 `체력이 가장 낮은 적`, `캐릭터 정면`
- 노드 획득과 파밍. 모든 노드 종류를 개수 제한 없이 쓸 수 있다.
- 마법 슬롯 여러 개, 속성(화염·냉기) 상성, 빔·장판 같은 다른 발현 종류
- 전투 후 실행 로그, 느린 재생 관찰 모드
- 그래프 저장·공유
- 적 AI, 적 생성, 웨이브 (기존 시스템을 따른다)
